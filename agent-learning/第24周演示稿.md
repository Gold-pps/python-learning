## 第 2 部分：系统是什么（2 min）

### 链路（讲这张图，别逐行念）

```text
① 解析      PDF / Word / Markdown → 文本 + 页码        pypdf / python-docx
② 切分      300~500 字/片、重叠 50 字
③ 向量化    BAAI/bge-small-zh-v1.5（ONNX，CPU，不上云）
④ 索引      chunks.jsonl + vectors.npz + meta.json（支持增量重建）
⑤ 检索      BM25 稀疏 + 向量稠密 → RRF 按**名次**融合
⑥ 重排      模型把 top20 压到 top5（只在"分不开"时调）
⑦ 综述生成  「盘点缺口 → 补检 ≤1 轮 → 组织四段式」两次调用
⑧ 引用校验  拿候选集合对账：精确 / 缺定位 / 编造 三档
```

三个设计选择（被问就讲这三条）：

- **为什么按名次融合（RRF）**：BM25 分数没有上界、还可能为负，余弦在 [-1,1]，
  两者量纲不可比；按排名融合天然免疫；
- **为什么是"两次调用的流水线"，不是让模型自己决定检索几轮**：
  SDK 的工具循环里"模型自己决定"= **成本不设上限**；改成"盘点 + 组织"两次调用，
  多跳最多一轮、补检查询 ≤3 条，钱的账能算清；
- **为什么引用校验写在代码里**：提示词里写"要挂引用"只是**请求**，模型完全能编一个像样的页码。
  只有把候选集合交给代码，才能把"看不出来"变成"能计数"。

### 界面（第 23 周）

浏览器打开即用，**不需要命令行**：

- 提问 → 四段式答案；**每条引用是个可点标签**，点开看该片段的原文全文
  （还会显示召回通道、融合分、稠密/稀疏排名）；
- 每次回答显示**耗时（检索 / 模型分开）+ token（含缓存命中）+ 估算成本**；
- 引用分三档显示：**红底 = 回查不到**（不在候选里），虚线 = 只到文件；
- 资料撑不住时，界面顶部写明"**下面是相邻证据，不是这个问题的答案**"。

## 第 4 部分：数据（2 min）

### ① 检索：重排值这个钱（25 条评测集，Top-5 严格判据）

| 方法 | 有答案（10） | 跨文档（5） | 多跳（5） | 合计（20） |
| ---- | ------------ | ----------- | --------- | ---------- |
| 关键词基线（第一阶段的做法） | 1/10 | 0/5 | 0/5 | **1/20** |
| BM25 | 5/10 | 0/5 | 2/5 | 7/20 |
| 纯向量 | 4/10 | 1/5 | 1/5 | 6/20 |
| 混合（RRF） | 5/10 | 0/5 | 2/5 | 7/20 |
| **混合 + 重排** | **8/10** | **2/5** | 2/5 | **12/20** |

达标线是"有答案类比关键词基线高 ≥15pp"，实测 **+70pp**。
**注意口径**：这组数字跑在笔记语料上（`--index data/index-notes` 可复现），真实论文语料上是另一套；
换语料后必须重测——**判据改了、语料换了，就必须重跑，否则分数没有意义**。

### ② 质量：编造 = 0 是代码保证的，不是模型自觉的

- 引用校验三档：**精确 / 缺定位 / 编造**，编造**单独记账、不静默删除**（删掉就看不见问题了）；
- 人工抽查可回查：第 21 周 4/4、第 22 周 5/5 逐字一致（含数值型结论）；
- 无答案拒答：**5/5**（资料里没有就说没有）。

### ③ 成本与性能

| 项 | 数值 |
| -- | ---- |
| 建库（44 篇全量） | **101~118 秒**（增量重建按内容 hash 跳过） |
| 一次问答 | 20~40 秒，**最多 2 次模型调用** |
| 单次花费 | 约 $0.003~0.01（**2~7 分钱**，低谷价再减半） |
| 第 23 周 26 次真实提问 | 合计约 **$0.1005（0.71 元）** |

**成本控制**：候选上限 10 条、单条截断 600 字、每段 ≤4 条、指令前缀稳定吃缓存、重活放低谷时段。

## 第 5 部分：局限（2 min，**这部分比能力更该讲**）

### 5.1 能力边界在语料上，不在模型上

拿实验室方案里想要的模块逐条去数语料：

| 方案模块 | 语料覆盖 | 结论 |
| -------- | -------- | ---- |
| 大模型与智能体辅助（工艺知识整理、相似案例检索） | 关键词 **0 片段** | ❌ 本库支撑不了 |
| NC 程序检查（语法 / 模态 / 安全点） | **0 / 0** | ❌ |
| 案例检索（"相似案例"） | **0 / 0** | ❌ |
| 工艺知识 / 知识图谱 / 工艺设计 | 3 / 4 / 4 片段 | ⚠️ 极薄 |
| 后处理 | 1 片段 / 1 篇 | ⚠️ |
| 仿真 / 数字孪生 | 229 / 288 片段 | ✅ 但偏**车间级** |
| 磨损 / 热误差 / 切削力 / 参数优化 | 382 / 148 / 132 / 65 片段 | ✅ |

一句话：**本库覆盖"加工机理 + 监测 / 优化 / 仿真 / 补偿"，不覆盖"AI 辅助工艺编制 + NC 代码工程"。**

### 5.2 已知缺陷（会影响你读数）

| 缺陷 | 你会看到什么 | 现状 |
| ---- | ------------ | ---- |
| 表格 / 公式被拍平 | 引用数值指向"一串数字" | 接受（解析器限制），数值必须回原文核对 |
| 答案可能"拿错语境" | 数值/方法看似可用实则不适用 | 提示词已加"语境保真"两条，实测有效但仍靠人读 |
| 转引他文的结果 | 出处对、归属错 | 已登记 |
| 术语同词不同义 | "智能体"= RL 调度 agent ≠ LLM 智能体 | 提示词要求显式说明（实测它会主动指出） |

### 5.3 自评的边界（**最容易忽略的一条**）

- **引用校验只能保证"没编造"**，挡不住"引用是对的、结论被误用"；
- **判据本身也会错**：参考文献段标记的第一版判据把 **26.6% 的正文页**标成了文献表
  （测试全绿——因为它只验证"该标的标了"，没验证"不该标的没标"）；
- 所以流程是**两道**：代码校验 + **人读关键条目**。只讲前者就是在自欺欺人。

### 5.4 我犯过的错（讲出来比藏着更有说服力）

| 事故 | 现象 | 教训 |
| ---- | ---- | ---- |
| 输出预算设 4096 | 四段式答案 **3/3 被截断**（一题连答案都没开始写） | 预算 = 产物长度 **+ 模型思考长度**；贴着实测值给等于没给 |
| 追问判据按"句子短" | 同样 7 个字，一句该带上文、一句不该，两轮都判错 | 判据的特征要挑"目标里几乎不会出现、噪声里才有的" |
| 界面进度条没渲染 | 离线测试全绿，界面上什么都不显示 | **"协议测过了"不等于"界面画出来了"**——补了一层迷你 DOM 冒烟 |
| 口令示例用了中文占位符 | 使用者照抄后请求根本发不出去 | HTTP 头只装 ISO-8859-1；**示例会被原样照抄，必须能用** |

## 备用问答（Q&A）

**Q1：为什么不用向量数据库（Milvus / Chroma / pgvector）？**
A：规模用不上。2501 个片段用 numpy 暴力余弦是**毫秒级**，落盘就三个文件
（`chunks.jsonl` / `vectors.npz` / `meta.json`），能 diff、能人工打开看。
按 300 篇估算也就 3000~7500 片段，5 万片以内都不需要换方案。

**Q2：怎么保证引用不是编的？**
A：提示词里写"必须挂引用"只是请求。真正的保障是**代码拿候选集合对账**：
引用必须来自给过模型的那 10 条候选，分三档记账（精确 / 缺定位 / 编造），
编造**不静默删除**、单独计数。目前累计 458 条引用，编造 0；另有人工抽查 9/9 逐字一致。

**Q3：成本会不会失控？**
A：一次问答**最多 2 次模型调用**（盘点 + 组织），补检最多一轮、≤3 条查询；
候选上限 10 条、单条截断 600 字；每段 ≤4 条。实测单次 2~7 分钱，
第 23 周 26 次真实提问合计 0.71 元（含 6 条高峰时段）。

**Q4：数据会不会外传？**
A：会外传的只有**你的问题**和**被检索到的候选片段**（每次 5~10 条，单条 ≤600 字）——
模型必须看到这些才能组织答案；语料文件本身、索引、其余片段都不出网；
API Key 只在本地 `.env`，日志写在 `data/`（不进 Git）。

**Q5：为什么不直接用大模型写 NC 代码？**
A：两个原因。一是**本库这块覆盖为 0**（关键词命中 0 片段）；
二是这类任务需要几何 + 工艺 + 机床后处理的全链路数据，且错误代价高。
当前系统的定位是"**把你手头已有的资料整理成带出处的答案**"，不是"替你做工艺决策"。

**Q6：为什么答案是四段式，不是一段自然语言？**
A：因为综述型问题的答案要**跨多篇**组织，"一大段散文"没法逐条核对出处。
固定键名才能做 JSON 约束 + 引用对账 + "某段没有依据"的空段声明。

**Q7：检索为什么非要加"重排"这一步？**
A：RRF 只看名次、不看命中质量（"命中多个常见词"会压过"命中一个精确词"，实测踩过）。
重排让模型真的读一遍候选再排序：合计 7/20 → 12/20，有答案类 +70pp。
代价是每题多一次调用，所以只在"分不开"时才触发。

**Q8：这套东西能不能直接用到别的语料上？**
A：能，换语料是固定动作：先 `python -m rag.index scan` 预检（失败 / 空文档 / 文字层可疑三个清单），
再 `build --all --verify --report` 一键重建 + 对齐校验 + 建库报告。
但**两件事必须重做**：评测数字要重跑（换语料后旧的对比表不再成立）、
能力边界要重新数（这次的"0 片段"清单就是这么来的）。
