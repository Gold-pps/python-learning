## 一、H1：让"使用数字"可复现（先做这个，因为它在撒谎）

而**没有任何测试会发现**。根因不是"忘了改"，是**数字靠人手抄**。

2. README 的"**N 篇 / M 片段**"必须等于 `data/index/meta.json` 的 `n_files`/`n_chunks`
   （没有索引时 skip——CI 上没有 `data/`，这条不能红）。

### 它上线当场抓出两处谎

| README 写的 | 日志实测 |
| ----------- | -------- |
| 累计 **0 编造** | 37 次问答里**有 1 条编造** |
| **26 次**真实提问 | **37 次**（2026-10-09 ~ 10-20） |

两处都改准了，而且**"承认 37 次里有 1 条编造"比含糊的"0 编造"更可信**。

### 还补了一个字段

日志里**根本没有 `cost`**——"花了多少钱"一直靠手记（那个核不出来的"574 条"也是同一原因：

## 二、H2：补资料一条命令（四步，每步都有中断规则）

`uv run python -m rag.refresh`：预检 → 全量重建 → 检索冒烟 → 报"哪几处文档数字过期了"。

**真跑一遍（66 篇 / 3724 片段）**：

| 步 | 实测 |
| -- | ---- |
| 预检 | 文件 66、片段 3724、**失败 0**、空文档 0 |
| 建库 | 全量重算 3724 片段、退出码 0 |
| 冒烟 | 7 题 **33/35**（NC 类 5/5）——**与补资料后完全一致**，重建是确定性的 |
| 待改文档 | **3 处**（历史叙述残留） |

**踩到的坑，而且是熟病**：第 4 步第一版在真实语料上报了 **58 处**——历史记录里的
"44 篇入库""2501 片段"全被列出，**等于没筛**。这就是 T52 的同一个病（"命中率太高的判据就是噪声"）
**第二次发作**，所以记了 **T58**。加两道闸（只认"描述现状"的写法 + 含"历史/第 N 周/补前"的行整行跳过）
后降到 3 处；粒度是**按行**的，边界写进了测试断言。

## 三、H3：**我把这一项改了主意**（本阶段最该记的一次判断修正）

原计划：**开机自启 + 索引备份**。动手前重新问了一遍"这值不值得做"，两处都错了：

### ① 自启：收益抵不上风险

常驻监听（绑 `0.0.0.0` 就可能被同网段试口令）、"自动拉起的那个"与"我刚改完重启的那个"分不清、
排障多一层判断；而这个项目一个多月只用过 **37 次**——**手动三行命令的代价远小于常驻风险**。
**砍掉**，改成把"手动三步启动"写进 README 首屏。

### ② 备份对象搞反了

`data/index` 是**派生物**：66 篇重建一次 3724 片段、约 3 分钟（`rag.refresh` 干的就是这个）。
而 **`data/corpus/` 那 66 篇 PDF 既不在 Git（`data/` 在 `.gitignore`）、也没有任何备份**——
**那才是唯一不可替代的资产**。

### 改成了什么

`rag/backup.py`：`--check`（三方对账：语料 / 索引 / README）+ `--backup`（打 zip）。
**恢复演练真做过**：159.5 MB zip → 解压到独立目录 → 恢复 **66 篇 = 原始 66 篇**，子目录结构保留 ✓。

> 这条记的是**顺序**：先问"这件事解决什么问题"，再问"怎么做"。
> 我原来的写法是"因为要显得完整，所以加自启"——那正是这个仓库一直在防的东西。

## 四、H4：一份可交付的综述包（第一次有"拿得出手的东西"）

5 个主题（含新补的两类）：**79 条结论 / 89 条精确引用 / 0 编造 / 0 无引用 / $0.0319 ≈ 0.23 元**。

两处复用而非新写：

- 正文调 `web.service.render_view_markdown`——**与界面、导出同源**，"包里读到的"就是"界面上看到的"；
- 视图 JSON 全部留档（5 份 150 KB）：换格式重导出**不再花钱**。

包里第三块是**抽查 5 条**：机器只判"结论里的数字/型号在不在它引用的那段里"（同页另一段 / 别的候选 /
候选里都没有），**结论对错明确标着"待人确认"**。

**抽查结果（2026-10-26，使用者核对）**：机器挑出的 5 个数字（`11.1`、`4.5`、`34.9`、`8.2`、`103.9`）
**在原文里全部找得到** → 5 条全判**支持**。

其中最值得记的是 `103.9`：机器说它"**候选片段里都没有**"，而人查原文发现**有**。
这正是 **T53 那条粒度教训的第二次实证**——**"模型看到的 600 字片段里没有" ≠ "原文没有"**。
所以那句提示（"候选片段里都没有"）是**准确的**，不能读成"编造"；要判编造，必须去 PDF 里搜全文。

## 四之二、**第一次被外部材料检验**（这一阶段最有价值的一件事）

前面所有指标都是**自证**的（检索覆盖、引用 0 编造、覆盖 33/35）。这一节是第一次拿**外部标准**去问：
"系统答得够不够全？"

**外部标准从哪来**：语料里那些**综述型论文**，它们自己的目录就是一份"应该覆盖什么"的清单。
工具 `eval/review_contrast.py` 把综述的章节标题与系统产出并排（**机器不打分**，只呈现）；
判断由人做——**而"数覆盖面"这件事不需要专业背景**。

### 实测（`刀具磨损状态监测综述_制造技术与机床2026.pdf` vs 综述包第 01 主题）

| 综述章节 | 系统 | 说明 |
| -------- | ---- | ---- |
| 1 类别及特点 | ✅ 覆盖 | 直接/间接两大类，直接法列了 4 种 |
| 2 传感器的选择 | ✅ 覆盖 | 力、振动、电流与功率、声发射、多传感器融合**都对得上**（人已核） |
| 3 特征提取技术 | ⚠️ 部分 | 只提小波包与深度学习，**没有时域/频域/时频域的谱系** |
| 4 建模方法（机器学习/深度学习/混合） | ⚠️ **部分，漏得最多** | 只讲深度学习；**SVM、HMM、混合模型一个都没作为方法讲**（人已确认） |
| 5 研究难点及发展 | ⚠️ 部分 | 提了两大困难，未展开趋势 |
| 6 结语 | — | 不算覆盖项 |

### 结论

> **系统把"磨损状态识别"讲得很全，对"磨损量/寿命的建模方法谱系"基本没覆盖。**
> 一句话：**对"监测"覆盖好，对"建模/预测"覆盖差。**

**可用性判断（能直接用的范围）**：能用于组会的"方法与传感器"部分；
**不能**直接用于"建模方法对比"——那部分要么自己补，要么先补资料再重跑。

### 细化诊断：六类缺口里，**只有一类是真缺资料**（2026-10-26）

对照之后第一反应是"补资料"。动手前先查了一遍**每类到底是缺资料、还是没被检索/没被写出来**：

| 建模方法（综述 §4） | 语料里有吗 | 进了候选吗 | 归属 |
| ------------------- | ---------- | ---------- | ---- |
| HMM（`EMD-PSO-HMM` 2024） | ✅ | ❌ | **检索问题** |
| 混合模型 A（机理-数据融合·在线监测 2026） | ✅ | ❌ | **检索问题** |
| 混合模型 B（机理-数据融合·预测 2026） | ✅ | ❌ | **检索问题** |
| BiLSTM（DRSN-BiLSTM 2024） | ✅ | ❌ | **检索问题** |
| Transformer（YOLOv11-Seg 2025） | ✅ | ❌ | **检索问题** |
| 剩余寿命预测（研究进展 2025） | ✅ | ✅ 进了 | **生成侧没写成方法** |
| 支持向量机 / 经典机器学习 | ❌ **没有** | — | **真缺资料** |

**再排除了"top_k 太小"这个猜想**（免费实测，同一道题）：

```
top_k= 5   候选 2 篇    那 5 篇：一篇都没进
top_k= 8   候选 3 篇    全没进
top_k=12   候选 5 篇    全没进
```

所以不是"排不下"，是**排序被综述/进展类论文占据**——问"有哪些主流方法"这种泛问题，
带"综述/进展"字样的论文天然得高分，单方法论文永远挤不进前几名（每篇≤2 只防"同一篇霸榜"，
**不防"全是综述"**）。

> **这条纠正了我最初的两个判断**：① 不是"缺资料"（8 类里 6 类语料都有）；
> ② 也不是"加深就行"（top_k 到 12 仍然一篇都进不来）。
> 真正该做的是**检索侧**：让多跳补检去生成"具体方法名"的查询（`多跳检索` 机制已存在，
> 这类问题没触发它），以及考虑"同一篇综述最多取 1 条"。

### 补资料能不能救覆盖？**不能——它只救"有没有"**（2026-10-27）

按上面的诊断补了 **4 篇**（SVR / 随机森林 / 深度学习在线识别 / 寿命预测综述），
语料 **66 篇 / 3724 片段 → 70 篇 / 3906 片段**（解析失败 0、193s、向量校验通过），
冒烟仍是 **33/35**（一篇没挤掉）。然后做了一组对照：

| 动作 | 成本 | 结果 |
| ---- | ---- | ---- |
| 补这 4 篇 | 免费（下载） | `SVM / 经典 ML` 从 **❌ 语料没有 → ✅ 有** ✓ |
| 泛问题上重测（`top_k=5/8/12`） | 0 元 | 这 4 篇 **一篇都没被检索到** ✗ |
| **按方法名直接问**（`SVR 支持向量回归 刀具 剩余使用寿命`） | 0 元 | **目标在 top3** ✓ |
| 多跳补检模拟（6 条方法名查询，合并封顶 10） | 0 元 | 7 个目标里只进来 **1 个**（base 占 8 席，补检只剩 2 席）✗ |

**两条独立证据，同一个结论**：

> **补资料解决的是"库里有没有"，解决不了"泛问题上捞不捞得到"。**
> 那一节综述题问的是"有哪些主流方法"——这类**泛问题**的排序天然被综述/进展论文占据，
> 单方法论文（HMM / BiLSTM / SVR / 随机森林）**再补多少篇也挤不进前几名**。

**三个待定改法（都没做，因为都会改变所有问答的行为）**：

| 改法 | 代价 |
| ---- | ---- |
| 合并候选上限 10 → 15/20 | 每次问答的 token 变多（贵一点） |
| 补检命中时**重置**候选（只留补检结果） | 可能丢掉 base 里的综述证据 |
| 每篇上限 2 → 1 | 候选更多样，但同一篇的上下文会被拆散 |

**为什么先不改**：这三个都是"全局旋钮"，而现有证据只有**一道题 × 7 个目标**。
先记录、等真的出现"必须覆盖方法谱系"的需求再动——这比凭一道题就改生产默认值稳。

### 这件事为什么比指标重要

1. **它把"自证"变成"他证"**：33/35 的覆盖只是"检索捞到了"，这次是"**产出与一篇已发表综述逐节对照**"；
2. **它给出了下一个具体缺口**：不是"再加功能"，而是"建模方法这一块语料/产出都不够"——**这才是能被真实需求驱动的方向**；
3. **它顺手验证了边界**：系统"有、综述没有"的两条（切削比能、换刀点取转折点）都来自 2025 年新文献，
   **回原文能查到引用** → 说明它没有编造，只是比那篇综述更新。**这条正好又一次说明"引用可核 ≠ 结论正确"**。

## 六、三条规律（这一阶段真正学到的）

1. **文档里的数字，要么给命令、要么带口径**。写过三次的东西不该第四次靠人记得改——
   T56 的解法不是"下次注意"，是**守卫测试**（裸累加值禁写 + 语料规模对账）。
2. **命中率太高的判据就是噪声**（T52 → T58 第二次发作）。
   "42/46 全被标""58 处待改"跟"一条不报"一样没用；判据的价值在**能把范围缩到看得完**。
3. **先问"值不值得做"，再问"怎么做"**。自启与备份对象这两处，都是计划阶段就想错、
   动手前问一句才发现——**计划里的"完整性"最容易变成无用功**。
