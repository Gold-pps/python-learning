## 2. 关键实现

### 2.1 大小检查必须放在读取之前

`read_note` 有 1MB 上限，`search_notes` 直接 `read_text()` 全量读入。加检查时容易写成：

```python
lines = p.read_text(encoding="utf-8").splitlines()   # ← 先读了
if p.stat().st_size > MAX_FILE_BYTES:                # ← 再检查，晚了
    continue
```

正确顺序是先 `stat()` 判断再读。同一份 `MAX_FILE_BYTES` 在两个工具里采取**不同策略**：
`read_note` 报错（用户要的就是那一个文件，静默返回空内容更糟），`search_notes` 跳过并回传
`skipped_large_files` 计数（一个坏文件不该让整次搜索失败，但也不能让模型把"没搜到"当成"笔记里没有"）。

### 2.2 会话历史收敛到常数规模（本周设计含量最高的一段）

`ask()` 原来直接 `return result.to_input_list()`，history 只增不减。改动是加两个上限
（`MAX_HISTORY_TURNS = 8`、`MAX_HISTORY_ITEM_CHARS = 2000`）和四个函数，
收敛动作只放在**写入侧一处**：`return result.final_output, prepare_history(result.to_input_list())`。

三个不变量（都是踩过或差点踩的坑）：

1. **必须从 `user` 消息处切开**。一轮 = 一条 user 消息 + 它引发的 `function_call` /
   `function_call_output` / 最终回答。从中间切会留下孤儿工具结果，发给 API 直接拒——而且只在被截断的那一次暴露；
2. **只在一个地方收敛**。history 是"只在这里写、只被下一轮读"的数据，两处各截一次的逻辑迟早分叉；
3. **截断返回副本**（`dict(item)` 重建）。工具返回值是"这一轮模型要看的资料"，历史副本只是"下一轮要记住的东西"，两者不能混。

### 2.3 密钥改环境变量注入

`~/.codex/config.toml` 里的 `experimental_bearer_token = "sk-…"` 换成 `env_key = "DEEPSEEK_API_KEY"`，
密钥本体放 `~/.config/deepseek/api.env`（600），由 `~/.bashrc`、`~/.profile` 各引一次；
因为 VS Code 是 systemd 直接拉起的（`ps` 显示父进程是 systemd、`/proc/<pid>/environ` 里没有该变量），
再补 `~/.config/environment.d/deepseek.conf`（600）+ `systemctl --user import-environment`。

### 3.4 T3 的真实 token 曲线（两臂对照，2026-09-18）

脚本：`notes-qa/exp_history_tokens.py`；`--no-trim` 一臂把 `result.to_input_list()` 原样存下，
等价于 T3 修复前那一行，其余路径完全相同。8 轮同一组问题，`temperature=0`。
原始数据：`notes-qa/after.json`、`before.json`。

| 轮 | 收敛臂：输入 / API 请求数 / 缓存命中率 | 不收敛臂：输入 / 请求数 / 命中率 |
| --- | --- | --- |
| 1 | 7,659 / 4 / 58% | 15,297 / 5 / 74% |
| 2 | 22,268 / 3 / 77% | 21,477 / 3 / 87% |
| 3 | 29,091 / 3 / 73% | 29,287 / 3 / 93% |
| 4 | **118,640** / 7 / 89% | **81,097** / 5 / 92% |
| 5 | 94,033 / 4 / 83% | 89,001 / 4 / 97% |
| 6 | 56,676 / 2 / 72% | 79,530 / 3 / 96% |
| 7 | 30,392 / 1 / 82% | 90,161 / 3 / 97% |
| 8 | 30,814 / 1 / 91% | 97,565 / 3 / 99% |
| **合计** | **389,573 / 25 次 / 82%** | **503,415 / 29 次 / 95%** |
| 低谷价估算 | 0.151 元 | 0.080 元 |

**结论一：这个修复在 8 轮规模下几乎没生效。**

- `MAX_HISTORY_TURNS = 8`：8 轮正好用满窗口，**上限从未触发**；
- `MAX_HISTORY_ITEM_CHARS = 2000`：两臂 history 体积几乎相同（79,712 字符 vs 83,695 字符，
  条目平均约 800 字符），说明**单条截断也几乎没触发**——真实工具返回比想象的短。

所以"token 曲线被止住"没有出现：两臂都在涨（4.02× 与 6.38×），差异主要来自别的变量。

**结论二：真正的主导变量是"这一轮里工具往返了几次"，不是历史有多长。**

单轮输入 token ≈ 该轮 API 请求次数 × 每次要重发的上下文。请求次数完全由模型当轮决定，
实测在 **1~7 次之间波动**（第 4 轮 7 次请求 → 118,640 token；第 7 轮 1 次 → 30,392 token）。
history 在 8 轮里只涨了 6 倍，而请求次数的波动就有 7 倍——后者的杠杆更大。

**结论三：本实验的噪声大于要测的效应，n=1 不足以比较两臂。**

第 1 轮两臂走的是**完全相同的代码路径**（空历史、同一个问题），却跑出 7,659 vs 15,297（**2 倍**）。
连第 1 轮都对不齐，后面逐点比较就没有意义。想比较必须：同一臂重复 3 次取中位数，
或者换一个不受模型行为影响的观测量。

**结论四（待验证的机制假设，但很值钱）：截断可能反噬缓存。**

收敛臂整体缓存命中率 **82%**，不收敛臂 **95%**。一个合理解释是：截断改变了历史内容，
下一轮请求的前缀与上一轮已缓存的前缀不再一致 → 命中率下降。
而缓存命中价只有未命中的约 1/50（见第 7 周笔记），**破坏缓存的代价很可能大于省下的 token**。
本次样本量不够（1 轮、请求数也不同），不能当结论——但它是下一轮实验最该验证的一条。

**结论五：参数是拍的，实测才是尺子。**

`8 轮 / 2000 字符` 是照"想象的使用方式"定的；实测的真实使用方式是"**一次提问 1~7 次工具往返、
单条工具返回平均约 800 字符**"。所以要么把上限调到真会被触发的量级（例如窗口降到 4 轮、
或单条降到 1000 字符），要么承认它只对 >8 轮的长会话起作用——**下次用 15~20 轮重测**。

由此得到第 22 周"定向优化"的正确优先级顺序：

1. 减少不必要的工具往返（搜索命中就够时不要 `read_note` 全文）——杠杆最大；
2. 控制单次读取规模（`read_note` 的默认 120 行 / 上限 200 行）；
3. 保持前缀稳定以提高缓存命中率（**别为了省 token 破坏缓存**）；
4. 最后才是历史窗口收敛（T3 做的这件事）。

## 4. 踩坑

1. **检查写在读取之后 = 没检查**。功能"看起来加了"，实际一点内存都没省。
2. **`os.rmdir()` 删符号链接会抛 `NotADirectoryError`**，被 `except OSError: pass` 吞掉后表现为
   "测试全绿 + 仓库多一个断链"。清理逻辑的失败必须另有观测手段（`ls` / `git status`），不能靠测试绿灯倒推干净。
3. **截断历史不能从中间切**：孤儿 `function_call_output` 会被 API 拒，而且只在会话够长时才暴露。
4. **别猜第三方库的数据结构**：`to_input_list()` 返回什么，我去 `.venv/.../agents/items.py:928` 读了源码才敢写截断。
   猜错的后果是"代码照跑、不报错、一个字符也没截到"。
5. **`auth.json` 对自定义 provider 不生效**。看着更优美的方案（凭据交给 Codex 自带的存储）实测 401，
   环境变量是唯一出路。
6. **`preferred_auth_method` 是当前版本不认识的字段**（`--strict-config` 报 unknown），目前在空转。发现即记录，不擅自删。
7. **想用配置屏蔽子 shell 里的凭据，这条路是死的**：`exclude`、`include_only` 都试过，都无效。
   否定结论同样要记，否则会反复试。
8. **最贵的坑：把验证输出原样贴进对话**。`systemctl --user show-environment` 的输出自带明文 Key，
   一贴就同时进了会话记录、本地 rollout/sqlite，并随上下文发给模型服务——代价是**换 Key**。
   教训：贴之前先做成"只看键名 / 只看长度"。
