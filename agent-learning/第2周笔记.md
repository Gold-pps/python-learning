> `学习进度.md` 的"第 2 周"章节与两个实际脚本（`00_first_api_call.py`、`01_hello_agent.py`）整理，

## 一句话结论

这一周刻意分成两步走：**先不碰框架**，用 `OpenAI` 客户端直接调 DeepSeek 跑通一次；
**再上框架**，用三段配置把 Agents SDK 的默认客户端指向 DeepSeek。
分两步的价值在于：出错时能立刻判断是"网络/Key 的问题"还是"框架配置的问题"。

## 1. 第 1 步：不经框架，直接调用（`00_first_api_call.py`）

```python
from openai import OpenAI

client = OpenAI(api_key=API_KEY, base_url="https://api.deepseek.com")

response = client.chat.completions.create(
    model="deepseek-flash",
    messages=[
        {"role": "system", "content": "你是一个耐心的老师。"},
        {"role": "user", "content": "用一句话解释什么是 Agent。"},
    ],
)
print(response.choices[0].message.content)
```

要点：

- 用的是**同步**客户端 `OpenAI`，没有 `asyncio`，适合先验证连通性；
- `base_url` 是关键：不写就默认发往 OpenAI；
- 这一步能跑通，说明 **Key 有效、网络可达、模型名正确**——三个最容易出错的点一次性排除。

## 2. 第 2 步：接上 Agents SDK（`01_hello_agent.py`）

```python
from openai import AsyncOpenAI
from agents import (
    Agent, Runner,
    set_default_openai_api, set_default_openai_client, set_tracing_disabled,
)

client = AsyncOpenAI(api_key=API_KEY, base_url="https://api.deepseek.com")

# 关键三步
set_default_openai_client(client=client, use_for_tracing=False)
set_default_openai_api("chat_completions")
set_tracing_disabled(disabled=True)

agent = Agent(
    name="History tutor",
    instructions="You answer history questions clearly and concisely.",
    model="deepseek-flash",
)

async def main():
    result = await Runner.run(agent, "罗马帝国是什么时候灭亡的？")
    usage = result.context_wrapper.usage
    print(result.final_output)
    print(f"请求数={usage.requests} 输入tokens={usage.input_tokens} 输出tokens={usage.output_tokens}")

asyncio.run(main())
```

## 3. 三段配置各自在干什么

| 代码 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `AsyncOpenAI(base_url="https://api.deepseek.com")` | 改掉请求地址 | 请求发往 OpenAI，401 或扣费在错的地方 |
| `set_default_openai_client(client, use_for_tracing=False)` | 让 SDK 默认用这个客户端；同时不上报 trace | 用 SDK 自带的 OpenAI 客户端 |
| `set_default_openai_api("chat_completions")` | 走 Chat Completions 兼容路径 | 走 Responses API，DeepSeek 不支持 |
| `set_tracing_disabled(disabled=True)` | 彻底关闭追踪 | SDK 尝试上传 trace，报错或产生额外请求 |

记忆方式：**"地址 → 客户端 → 协议 → 追踪"**，四件事一次配完，后面每个脚本都复制这段。

## 4. 概念清单（本周必须弄懂的 5 个名字）

| 名字 | 含义 |
| --- | --- |
| `Agent` | 把模型 + 指令（+ 工具）打包成的一个"角色" |
| `Runner.run(agent, input)` | 真正执行：把输入交给模型，处理工具调用循环，直到产出最终回答 |
| `result.final_output` | 最终回答（字符串） |
| `result.context_wrapper.usage` | 本次运行消耗：请求数 / 输入 token / 输出 token |
| `set_tracing_disabled` | 关掉 OpenAI 云端追踪，避免依赖 OpenAI 账号 |

同步 `OpenAI` 与异步 `AsyncOpenAI` 的区别：SDK 的 `Runner.run` 是 `async` 的，
所以接 SDK 时必须用 `AsyncOpenAI` 并配 `asyncio.run()`。

## 5. 本周产出与验证

- 产出：`00_first_api_call.py`（普通调用）、`01_hello_agent.py`（最小 Agent）；
- 验证：两个脚本均能正常返回中文回答；`01` 额外打印 token 用量，为第 7 周的成本统计打底；
- 理解验收：能口头解释清楚"请求为什么发到 DeepSeek 而不是 OpenAI"。

## 6. 坑与注意

- **`model` 不能照抄文档**：官方示例写 `gpt-*`，必须换成 `deepseek-flash`；
- **别把三段配置拆散**：只写 `base_url` 而不写 `set_default_openai_api("chat_completions")`，
  会走到 Responses API 报错；
- **`use_for_tracing=False` 别漏**：否则 SDK 可能仍按 OpenAI 的追踪链路走；
- Key 的报错文案要统一：两个脚本在缺 Key 时会直接 `raise SystemExit` 并提示
  "先在 platform.deepseek.com 创建 API Key"，比后面的 401 更容易定位。

## 7. 复盘（补写时整理）

- **分两步走是对的**：先同步调用、再异步框架，出问题时排查范围小了一半；
- **最容易被低估的一点**：`base_url` 只是"换个地址"，真正让 SDK 换掉后端的是那段三段配置，
  这也是后来每个脚本都带一段重复样板的原因（第 12 周复盘时列为可优化项）；
- **顺手加 usage 打印回报很高**：一次三行代码，第 7、9、10 周的成本分析全靠它。
