## 第 4 部分：项目演示（3 min）

### 项目是什么

`notes-qa`：个人笔记问答助手。

### 怎么工作

```text
用户问题
  → Agent 决定搜索
  → search_notes 关键词搜索
  → 必要时 read_note 读取上下文
  → 基于原文回答 + 引用来源
  → 找不到就说"笔记中没有找到"
```

### 现场演示（1 min）

依次问这 3 个问题，覆盖三种典型行为：

| # | 问题 | 预期表现 |
| - | ---- | -------- |
| 1 | 第 7 周讲了什么？ | 跨文件搜索 → 读取 → 回答并给出行号引用 |
| 2 | 它提到的账单是多少？ | 直接用上一轮历史作答（请求数从 4 降到 1） |
| 3 | 笔记里有没有讲 Excel 怎么画图？ | 明确回答"笔记中没有找到"，不编造 |

**演示前检查**（避免现场翻车）：

```bash
# 需要联网 + agent-learning/.env 里配好 DEEPSEEK_API_KEY
cd agent-learning/notes-qa
python main.py
```

备用方案：网络不通时改用 `python eval_cases.py --unit-only` 演示 12 条单元测试（不需要网络）。

## 第 5 部分：关键收获（2 min）

**技术点 1：工具要"宁可返回错误，也不要抛异常"**

三个工具（`list_notes` / `search_notes` / `read_note`）统一返回
`{"ok": false, "error": "原因"}`，模型能看到原因并换一种方式重试；
实测畸形参数（`None`、`'many'`、非整数行号）都被结构化错误接住，不会打断整轮对话。

**技术点 2：安全边界要在工具层做，不要在提示词里"请求"模型**

- 路径 `resolve()` 后校验是否仍在笔记根目录内，拦下 `../`、绝对路径、符号链接 / junction 逃逸；
- 只允许 `.md`，排除 `.env` 与 `notes-qa/`；单文件 ≤ 1MB、单次 ≤ 200 行、搜索 ≤ 5 条；
- 最有价值的一次发现：仓库根建一个名为 `xxx.md`、指向外部目录的 junction，
  `search_notes` 会跟着读出去——这是靠"主动构造攻击场景"才发现的，人肉 review 看不到。

**技术点 3：评估脚本本身也要被评估，成本要能解释**

- 期望词要选"语义必然出现"的稳定词（"检查时机""输入护栏"），并先归一化再去匹配；
  第 9~11 周踩过两次假阴性、一次假阳性；
- 反直觉发现：**无答案问题比有答案问题更贵**，模型会为了确认"没有"反复换关键词搜索（请求数 4 → 8）；
- 省钱结论：多轮历史比重新搜索便宜约 3 倍（第 2 问只花 1 个请求）；
- 当前评估：12 单元 + 3 模型 = 15 条；2026-09-15 复跑单元测试仍为 12/12（模型评估需联网、消耗 token）。

## 备用问答（Q&A）

**Q1：为什么用 DeepSeek，而不是直接用 OpenAI？**
A：不需要给 OpenAI 充值。做法是把 `AsyncOpenAI` 的 `base_url` 指向 `https://api.deepseek.com`，
再执行 `set_default_openai_client` / `set_default_openai_api("chat_completions")` /
`set_tracing_disabled(True)`，SDK 只当开发框架用，请求全部发往 DeepSeek。

**Q2：为什么不做向量检索？**
A：MVP 阶段刻意砍掉，先把"工具 + 循环 + 引用 + 不编造"跑通。
关键词匹配在笔记量小时够用，笔记变多后再上 embedding。

**Q3：15 条评估都是真跑的吗？**
A：是。12 条单元测试不走模型、不需要网络（2026-09-15 复跑 12/12）；
3 条模型评估走完整 Agent、需要联网并消耗少量 token。

**Q4：一共花了多少钱？**
A：2026-09-01 ～ 09-10 的 DeepSeek 账单是 20.7878 元；12 周总花费量级是"几十元"。
省钱做法：默认用 `deepseek-flash`、把批量评估放到低谷时段和周末、保持提示词前缀稳定以提高缓存命中。

**Q5：最大的坑是什么？**
A：Windows 下的 junction 逃逸——普通用户就能创建，`list_notes` 过滤了但它没过滤，
导致搜索会读到仓库根目录外的文件。修法是候选文件统一 `resolve()` 后再判断是否仍在笔记根内，
并补了 U6 用例覆盖。

**Q6：如果现场网络不通怎么办？**
A：跑 `python eval_cases.py --unit-only` 展示 12 条单元测试（无需网络），
并说明模型评估的部分你已经在本地跑通、通过率 15/15。
