### 动手前先知道这十条（都是本阶段真踩过的）

1. **模型评估由用户在自己时段跑**（会花 token）；AI 侧只跑 `--unit-only` 与离线测试。
   10 条一轮实测约 39 万 token（67 次请求），低谷价粗估 0.25~0.3 元；
2. **重活放低谷**：工作日 12:00–14:00、18:00–次日 09:00、周末全天，价格是高峰的一半；
3. **不要用 `git checkout --` / `git restore` 清临时改动**——它是文件级的，会把该文件
   **所有**未提交改动一起冲掉，而且不报错（台账 T9 的现场）；
4. **无答案题的关键词不能写进 `agent-learning/*.md`**——那等于把答案卡交给被检索的 Agent
   （台账 T8"发现一"）。题库与答案卡只写在 `notes-qa/` 内（该目录已在 `EXCLUDE_DIRS` 中）；
5. 未经用户明确要求**不要 `git commit` / `git push`**（仓库规则）。
6. **要"改坏代码做验证"，就复制到临时目录改**——第 14 周的变异测试（T13）就是这么做的；
   直接在仓库里改再还原，很容易变成 T9 那种事故；
7. **`ruff --fix` 之后必须重跑 `ruff check`**：它会删掉写法不规范的 `# noqa`，
   也可能把改动留在你没预期的地方（T12）；
8. **验证类脚本的输出要限流**：旧入口会把整个文件内容打进 FAIL 行，
   一次变异测试的输出能爆到 26 万 token（T14 附近记录）。Windows 上用
   `| Select-Object -First 50` 之类替代 `| cut -c1-100`；
9. **Windows 上开发**：命令是 PowerShell，不是 bash。路径用反斜杠，
   调 `.venv-rag` 里的解释器要加 `&` 前缀（`& ".venv-rag\Scripts\python.exe" ...`）；
   PowerShell 会把 `-c "长字符串"` 里的引号转义弄坏，**超过三行的脚本一律写成临时 `.py` 文件再跑**；
10. **跑 pytest 需要管理员权限**（或开启 Windows 开发者模式）：普通用户建不了文件符号链接，
     `test_read_note.py` 里的 `make_file_link` 会 skip。这是平台限制，不是代码 bug；
     Linux CI 上 46 条全跑。

### 常用命令（PowerShell）

```powershell
# 主环境（仓库根）
uv sync                              # 首次或换机后
uv run pytest -q -p no:cacheprovider # 62 passed
uv run ruff check .
uv run ruff format --check .

# RAG 环境（在 agent-learning\notes-qa 下）
& "..\..\.venv-rag\Scripts\python.exe" -m rag.index build
```

`-p no:cacheprovider` 用来绕开 pytest 收尾时清理临时目录的 Windows 权限报错（不影响测试结果）。

### Windows 平台限制

- **文件符号链接测试需要管理员权限**：普通用户建不了文件 symlink，
  `tests/test_read_note.py` 里 `make_file_link` 会 skip 1 条（Linux CI 上全跑，46 → 62 条全绿）。
  这是平台限制，不是代码 bug。要消除 skip 就开 Windows 开发者模式，或用管理员 PowerShell 跑；
- **PowerShell 转义**：`python -c "长字符串"` 里的引号会被吃掉，
  超过三行的脚本一律写成临时 `.py` 文件再跑；
- **调 `.venv-rag` 的解释器要加 `&` 前缀**：`& ".venv-rag\Scripts\python.exe" ...`。

# 主环境
