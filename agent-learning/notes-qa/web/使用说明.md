# notes-qa Web 界面 · 使用说明 + 能力边界声明

> 适用版本：第 23 周（2026-10-10）｜索引：`data/index`（44 篇 / 2501 片段）
> 第一次用请先读第 2 节的“能答什么、不能答什么”——它决定了你会不会白问。

## 1. 它是什么

一个跑在**你自己电脑上**的资料问答界面：底料是本机 `data/corpus/` 里的 44 篇数控 / 智能制造
中英文论文，回答由 `deepseek-flash` 生成，**每条结论都挂着 `[文件:页码]` 的引用，点开就能看原文片段**。
每次回答还会告诉你**花了多少钱、花了多久**。

它不是什么：不是搜索引擎，不是通用助手，不会联网查新资料，也不会凭空知道资料里没有的东西。

## 2. 能答什么、不能答什么（能力边界）

### 2.1 语料层边界（**最重要的一条**）

这一节直引 `agent-learning/汇报材料-技术版.md` 第 4.1 节。它是拿"实验室方案里想要的模块"
逐条去语料里数出来的，不是感觉：

| 方案模块 | 语料覆盖 | 结论 |
| -------- | -------- | ---- |
| 大模型与智能体辅助（工艺知识整理、相似案例检索） | 关键词 **0 片段** | ❌ 本库支撑不了 |
| NC 程序检查（语法 / 模态 / 安全点） | **0 / 0** | ❌ |
| 案例检索（"相似案例"） | **0 / 0** | ❌ |
| 工艺知识 / 知识图谱 / 工艺设计 | 3 / 4 / 4 片段（1~3 篇） | ⚠️ 极薄 |
| 后处理 | **1 片段 / 1 篇** | ⚠️ |
| 仿真 / 数字孪生 | 229 / 288 片段 | ✅ 但偏**车间级**，不是几何级刀轨碰撞验证 |
| 磨损 / 热误差 / 切削力 / 参数优化 | 382 / 148 / 132 / 65 片段 | ✅ |

**要支撑"AI + 智能制造实验室"的方案，第二期至少补四类资料**：
① LLM/Agent 在工艺设计与 CAPP 中的应用；② NC 程序检查与后处理；
③ 车削工艺与刀具（**本库以铣削为主**，`车削` 仅 63 片段/15 篇）；
④ 几何级刀轨与碰撞验证仿真。

一句话版本：**本库覆盖"加工机理 + 监测 / 优化 / 仿真 / 补偿"，不覆盖"AI 辅助工艺编制 + NC 代码工程"。**
问后者时它会老老实实说"资料中没有"——那是**功能正常**，不是故障。

### 2.2 已知技术缺陷（会影响你读答案）

| 缺陷 | 你会看到什么 | 现状 |
| ---- | ------------ | ---- |
| 表格 / 公式被拍平 | 引用数值时指向"一串数字" | 接受（PDF 解析器限制）；要数值得人工回原文 |
| 2 篇论文文字层损坏 | 检索层已排除这些片段 | 已排除（引用不出可读原文的源不进候选） |
| 参考文献列表页抢分 | 曾把文献表当候选 | 已标记 657/2501 并从候选排除 |
| 答案可能"拿错语境" | 数值 / 方法看似可用、实则不适用 | 提示词已加"语境保真"两条；**效果待真实使用验证** |
| 转引他文的结果 | 出处对、归属错 | 已登记（答案应保留"某某等提出"） |
| 术语同词不同义 | 如"智能体"= 强化学习调度 agent ≠ LLM 智能体 | 提示词要求显式说明差异 |

### 2.3 自评的边界（这条最容易被忽略）

- **引用校验只能保证"没编造"**：代码拿候选集合对账，挡不住"引用是对的、结论被误用"；
- **判据本身也会错**：第 22 周参考文献段判据第一版把 26.6% 的正文页标成了文献表；
- 所以流程是**两道**：界面上的引用校验 + **你自己读关键条目**。
  数值、工艺参数这类会被直接拿去用的结论，请点开引用回原文看一眼。

## 3. 启动

```powershell
# 一台机器上只需做一次（首次或换机）
cd c:\Users\czy\Desktop\github-repositories\python-learning
uv sync --extra rag                       # 主环境装 fastembed（ONNX+CPU，不含 torch）

# 建索引（已有 data/index 就跳过；这一步离线、不花钱）
cd agent-learning\notes-qa
uv run python -m rag.index scan           # 预检：能不能解析、有没有空文档
& "..\..\.venv-rag\Scripts\python.exe" -m rag.index build --backend fastembed --all --verify

# 启动（默认只绑本机）
uv run python -m web.server
# 浏览器打开 http://127.0.0.1:8000
```

先自检（不启动服务、不花钱）：

```powershell
uv run python -m web.server --check
```

它检查三件事：索引三件套齐不齐、`fastembed` 装没装、`agent-learning/.env` 在不在。

### 让局域网里的同学试用

```powershell
uv run python -m web.server --host 0.0.0.0 --token "自己起一个口令"
```

- **`--host` 不是回环地址时必须给 `--token`**，否则直接拒绝启动：这个服务会花你的额度，
  绑到 `0.0.0.0` 又不设口令，等于同网段任何人（以及他电脑上的任何脚本）都能拿你的 Key 提问；
- 口令不是账号体系（本项目明确不做鉴权），只是"别让路人白刷"；浏览器会把它存在本地；
- 连不上先看 **Windows 防火墙**是否放行该端口（本项目不会自动改防火墙）。

### 常用参数

| 参数 | 作用 |
| ---- | ---- |
| `--port 8000` | 端口 |
| `--index data/index-notes` | 换索引（如笔记快照库） |
| `--log data/usage_log.jsonl` / `--no-log` | 提问日志（默认开，本地文件、不进 Git） |
| `--thinking-model <模型名>` | 命中"综述型问题"判据时改用这个模型（**以控制台为准**，不给就一直用 `deepseek-flash`） |

## 4. 界面怎么读

- **提问**：Enter 发送、Shift+Enter 换行。上限 500 字符（与命令行同一条规则）；
- **进度**：检索 → 盘点 → 补检 → 组织，每一步都会亮起来。首次提问会多一步"加载检索模型"
  （1~3 秒，把向量模型读进内存）；
- **答案**：固定四段——研究现状 / 方法对比（逐方法列优缺点）/ 结论 / 可复用点。
  某段为空 = 候选不足以支撑这一段，不是渲染丢了；
- **引用点开看原文**：每条结论后面的灰底小标签就是引用，点一下会在下面展开**该片段的原文**，
  以及它来自哪条候选（召回通道、融合分、稠密/稀疏排名）。
  - 虚线边框 = **只到文件**（模型没给页码），会列出该文件本次命中的片段供人工核对；
  - 红底 = **回查不到**（不在模型看到的候选里），属引用校验的"编造"档；
- **成本与耗时**：每次回答下方显示"耗时合计 = 检索 + 模型""token 用量（含缓存命中）"
  "估算成本（美元 / 元，标注高峰或低谷价）"；页头有本次会话累计；
- **两个开关**：
  - *追问时带上上一问*（默认开）：带指代词或追问标记词的句子（"那**他们**的局限呢"、
    "**还有**呢？"）以及 6 字以内的极短句，会把上一问拼进检索词——**不额外调用模型，不加钱**。
    拼了没有、拼成什么，界面上都会写出来，不想用就关掉开关重问；
    （判据第一版按"句子短"来判，把“异星工厂是什么”这种独立小问题误当成了追问、
    检索被带偏，已修，见台账 T38。判据仍会误伤，所以界面上才把检索词摆出来。）
  - *多跳检索*（默认开）：先盘点"缺什么"、再补检一轮，多一次模型调用（约 +0.5 倍成本）。
- **资料缺口声明**：候选撑不住时，界面会明确写"资料中没有……"，而不是编一段给你。

## 5. 数据去哪了（外发说明）

- **会发往 DeepSeek API**（`https://api.deepseek.com`）：你的**问题**，以及**被检索到的候选片段原文**
  （每次约 5~10 条，单条上限 600 字）——模型必须看到这些才能组织答案；
- **不会外发**：语料文件本身、索引、其余没被检索中的片段、以及你的 API Key（Key 只在本地
  `agent-learning/.env`，由服务端读取后放进请求头）；
- **提问日志**：默认写在 `data/usage_log.jsonl`（本地文件，`data/` 已在 `.gitignore` 内），
  记录问题、耗时、token、引用计数与降级情况；`adopted` 与 `note` 两格**留空**，
  由人工补"帮上忙 / 帮倒忙"。给同学试用前若不希望留痕，用 `--no-log`。

## 6. 成本与计价口径

- 界面上是**估算**：价格快照是 **2026-09-10** 的官方价（每 100 万 token，`deepseek-flash`）：
  输入未命中 $0.15 / 缓存命中 $0.003 / 输出 $0.60，低谷价是高峰价的一半；
  高峰时段为北京时间周一至周五 09:00–12:00、14:00–18:00，其余时间与周末为低谷；
- 计价按时点自动选档，并把缓存命中的输入单独计价（它只有未命中价的约 1/50，
  不拆开会把成本高估好几倍）；
- **要精确对账请看 DeepSeek 平台的账单页**。官方随时可能调价，代码里没有"实时价格"这类东西。

## 7. 常见问题

| 现象 | 原因 / 怎么办 |
| ---- | ------------- |
| 启动就被拒（"索引或依赖不齐"） | 照提示跑 `--check` 看是哪一项；建库命令在提示里 |
| 提问报"索引不可用" | `data/index` 三件套不全（没有索引 / 刚清过缓存），重建即可 |
| 提问报"缺少向量化后端" | 主环境没装 fastembed：`uv sync --extra rag` |
| 回答被截断 / 内容不全 | 界面会标"降级"并给出原因；调大输出预算是改代码里 `REVIEW_ANSWER_MAX_TOKENS`，**先让每段写短更划算**（截断 = 这次调用全部白花钱） |
| 首次提问慢 2~4 秒 | 在加载向量模型（ONNX），只慢这一次 |
| 关掉页面后模型还在跑 | 已经发出的调用停不下来（钱也花了）。界面停了不等于请求取消了 |
| 追问时答案跑偏 | 关掉"追问时带上上一问"，或把问题写完整；界面会显示实际用的检索词 |
| 刷新页面后对话没了、追问也不带上文 | **有意如此**：会话状态只存在内存里（浏览器一侧 + 服务端一侧），刷新即清空。想留着就把问题复制下来，或在提问框里写完整 |
| "资料中没有找到相关片段" | 见第 2.1 节：这是**诚实拒答**，不是故障 |

## 8. 反馈

试用时最有用的是这三类信息：**问题本身**（原话）、**答案是帮上忙还是帮倒忙**、
**哪一条结论你回原文核对后发现不对**。前两类可以填进 `data/usage_log.jsonl` 的
`adopted` / `note` 两格，第三类直接说就行——它们比"感觉还行"值钱得多。
