## 一、核对做到了哪一档（先说清，否则数字会骗人）

| 项 | 情况 |
| -- | ---- |
| 核对者 | 使用者本人（**非机械 / 数控方向**） |
| 方式 | **快速浏览**（原话："我看了一下感觉都支持"） |
| 这一档能覆盖什么 | 读起来顺不顺、像不像论文里的话、有没有明显离谱的东西 |
| 这一档**不能**覆盖什么 | **逐条把结论与它引用的原文对照**——46 条 × 每条两段原文，那需要逐字读 |

**所以本轮不写"46 条全部支持"。** 按第 24 周定的口径，这只算"快速浏览通过"，
不能写成"逐条核对通过"。真正的核对要靠下面第二节那种"具体到某条某个数"的方式。

| 1 | `02 #15` | `103.9`、`0.46` | **有** | 它引用的候选里**没有**，其他候选也没有 | **支持**——依据在原文，**但不在模型看到的那一段**；模型越界写了个它没读到的数（恰好对） |

## 四、回灌（H3 第 4 项：至少一条闭环）

针对"数值/型号不在引用片段里"这一类，已经落到三处，不只写在报告里：

1. **提示词**（`rag/review_qa.py` 第 6 条规则）：数值与型号必须原样来自**你引用的那个片段**，
   不许把 A 片段的数值挂到 B 片段的结论上；原文没给数就写"显著降低"；
2. **代码核对**：新增 `unsupported_facts(payload, candidates)`，在 `answer_review()` 里自动跑，
   命中就写进 `reason`（`；硬事实待核 N 项`）与使用日志的 `unsupported_facts` 字段——
   **每次问答都会报，不依赖谁想起来跑工具**；
3. **测试**：3 条（数字在原文里不报 / 不在就报且带上引用位置 / 引用标记 `[5]` 不误抓）。
