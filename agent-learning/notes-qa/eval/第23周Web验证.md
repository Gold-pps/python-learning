### 4.1 缺陷一：进度条根本没渲染（前端，台账 T37）

| 项 | 内容 |
| -- | ---- |
| 现象 | 使用者反馈"checklist 第 2 条好像没有进度条"。整个提问过程界面只有输入框禁用，看不到"检索 / 盘点 / 作答"走到哪一步 |
| 根因 | `stepLine()` 里 `const line = el("li")` 之后只做了 `steps.set(key, line)`——**写进了 Map，却从来没 `appendChild` 到 DOM**。函数签名里也没有那个 `<ul>`，等于这段代码压根没地方可插 |
| 改法 | `stepLine(stepList, steps, event)`：补上 `stepList.appendChild(line)`，调用处传 `ctx.stepList` |
| 验证 | 手工：重新提问看到逐步亮起（`✓ 检索资料库 · 第 1 轮 · 命中 10 条 · 0.05s` → `◐ 盘点信息缺口` → …） |
| 影响面 | **后端一直是对的**（SSE 事件序列在离线冒烟里已验证过），坏的只是渲染。教训：这条恰好说明"协议测过了"不等于"界面画出来了"——前端没有自动化测试这件事因此从"低优先"升为待补项（第 6 节） |

### 4.2 缺陷二：追问判据把独立小问题当成了追问（台账 T38）

| 项 | 内容 |
| -- | ---- |
| 现象 | 问完“AI 辅助工艺编制怎么做？”（**正好 12 字**）之后问“异星工厂是什么”，界面显示"本次检索词带上了上一问"，日志里那一行是 `"AI 辅助工艺编制怎么做？ 异星工厂是什么"`——**候选整批跑到数字孪生 / 产线调度那边**，与所问毫无关系 |
| 根因 | 判据第一版是"长度 ≤ 12 或含指代词"。"句子短"这种特征**在追问里会出现、在独立小问题里也会出现**，拿它当判据就是给自己造噪声——与 T31（常量复用）、T36（文献表判据）是同一类错误：特征没挑"目标里几乎不会出现、噪声里才有的" |
| 改法 | 去掉纯长度判据，改成 **指代词 / 追问标记词**（它、他们、这个、那些、上述、还有、继续、展开说…）**或 6 字以内的极短句**（"还有呢？""为什么？"）。`web/service.py` 的 `_ANAPHORA` / `_CONTINUATION` / `FOLLOW_UP_MAX_CHARS` |
| 验证 | 新增回归测试 `test_follow_up_heuristic_does_not_swallow_short_standalone_questions`（把首跑那句原样钉住）+ `test_looks_like_follow_up` 补 5 个正反例；`pytest` 213 passed |
| 影响面 | 判据仍会误伤（"那优化呢？"里的"那"不在表里），但**界面上拼了什么、开关在哪都是明摆着的**——判错的成本被界面兜住了，这也是当初把检索词显示出来的原因 |

### 4.3 缺陷三：修 T37 时漏改了调用处（台账 T39，我自己造的）

| 项 | 内容 |
| -- | ---- |
| 现象 | 修完 T37、重启并强刷后，**提问瞬间**界面报 `连接中断：TypeError: Cannot read properties of undefined (reading 'stage')`（服务器其实照常跑完，日志里多了记录） |
| 根因 | 给 `stepLine` 加参数时**只改定义、没改调用处**：`stepLine(ctx.steps, event)` 让 `steps` 拿到事件对象、`event` 变成 `undefined`。JS 不会因为实参个数不匹配报警，直到真正访问 `event.stage` 才炸 |
| 改法 | 调用处补全为 `stepLine(ctx.stepList, ctx.steps, event)` |
| 验证 | **变异测试两处**：删掉 `stepList.appendChild(line)` → 报 `T37：进度行没有插进 DOM`；改回旧调用 → 报与现场一致的 `TypeError`。随后还原、复跑全绿 |
| 影响面 | 同一块功能**连续两次**坏在"画出来"这一步 → 缺的不是"更小心"，而是**一层不依赖浏览器的 DOM 测试**。现已补上（见下） |

**补的那层测试**：`tests/frontend_smoke.mjs` 把 `index.html` 的内联脚本当成函数体执行，
配四十行 `makeEl()` 迷你 DOM，覆盖：进度条真的进 DOM、四段与空段说明、三种引用状态
（精确 / 只到文件 / 回查不到）点开看原文、候选折叠，以及**真实 SSE 分帧到渲染的端到端**
（故意把一帧从中间切开，考验跨 chunk 拼帧）。由 `tests/test_web_frontend.py` 转接进 pytest，
**没装 node 就 skip**（它是附加保险，不是运行前提）。

### 4.4 缺口题的表现（这是首跑最值钱的一条）

拿“AI 辅助工艺编制怎么做？”去问（本库明确不覆盖，见 §4.1 的能力边界表），模型的表现是：

- 主动提示**术语不同义**："文献[7][9] 中的'智能体'指强化学习调度智能体（Q-learning 决策主体 /
  被赋技能标签的工人代理），与**大语言模型智能体**不同义，不能等同使用"——这正是第 22 周
  T35 加的两条"语境保真"要求在真实提问上的第一次生效；
- 主动给**数值加适用语境**："参数类数值（如 MRR 提升约 24.40%、n=1800~2400 r/min 等）
  均限定于其原文的铣削试验语境，不可外推"。

但**四段本身仍然填满了相邻领域的内容**（产线平衡、参数优化、数字孪生仿真），
