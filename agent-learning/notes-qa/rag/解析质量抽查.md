## 三、自动检测列出的可疑文件（2 篇，已决定"仅存在性可检索"）

```
数字孪生与智能车间/数字孪生五维模型及十大领域应用_计算机集成制造系统2019.pdf
  （18 个片段含 /G 字形编号）

  （5 个片段含 /G 字形编号）
```

**处置决定（使用者，2026-10-08）：不换版本，按"仅存在性可检索"使用。** 具体含义：

| 允许 | 不允许 |
| ---- | ------ |
| 作为"**这个方向有这篇文献**"的存在性证据（标题 / 期刊 / 年份 / 文件名可读） | 当作**正文来源**引用（片段里是 `/G21/G22`，回查不到任何可读原文） |
| 在"资料清单 / 覆盖率"类统计里计入 | 拿它的片段去支撑综述结论——第 21 周引用回查要**先看这份清单** |

两条推论：① 这两篇的片段是**纯召回噪声**：标题类关键词能命中，正文关键词永远命中不了，
所以它们会压低"看起来的召回率"却不贡献答案；② 若第 21 周发现某个子主题**只有**它们能覆盖，
再回头换版本（换完重跑 `index scan` + `build --all --verify --report`，别手工改报告里的数字）。

两条值得记的观察：

1. **同一本期刊命中两篇**（《计算机集成制造系统》，2010 与 2019 年）——这不是随机分布，
   更像是该刊某些年份的 PDF 文字层没带 ToUnicode 映射。**同一期刊的其它论文也要留意**；
2. 其中《数字孪生五维模型》那篇**不在我手工抽查的 5 篇里**——是自动检测抓出来的。
   这说明"人工抽 5 篇"只能看个大概，**规律性的质量体检要自动化**（已加进 `index scan`）。

## 四、对后续的影响与建议

1. **G3 的综述型问答不受影响**：那类问题要的是"有哪些方法、各自优缺点"，
   靠正文段落，不依赖公式与表格结构；
2. **两篇 `/G` 乱码的论文已决定"不换版本、按仅存在性检索"**（决定与边界见第三节）：
   第 21 周做引用回查时**先看这份清单**，别把它们的片段当引文；若某子主题只靠它们覆盖，
   再回头换版本；
3. **公式与表格数值暂时不要引用**：pypdf 把它们拍平了，引用会指向"一串数字"。
   若将来确实需要（例如"某文献的最优参数是多少"），再走规划里的 Vision 支线（转图片识字，会花 token）；
4. **换语料时的固定动作**：`index scan` 先看"失败 / 空文档 / 可疑"三个清单，
   再 `build --all --verify --report`。这次 44 篇的预检只花了 22 秒，比建库（103 秒）便宜得多。
