## 一句话结论

第 10 周在 MVP 基础上做了 4 件事：修 2 个遗留问题、加输入层保护、升级交互式循环、

## 1. 本周改动

### 1.1 read_note 补排除目录检查

原漏洞：`EXCLUDE_DIRS` 只在 `list_notes` 生效，`read_note` 能读到 `notes-qa/` 内的文件。
修复：在 `_safe_resolve` 末尾加排除目录检查。

验证：

| 输入                   | 结果                         |
| ---------------------- | ---------------------------- |
| `项目设计.md`          | 文件不存在（被排除目录挡住） |
| `notes-qa/项目设计.md` | 该路径在排除目录内，不可读取 |
| `config.py`            | 只允许读取 .md 文件          |
| `学习进度.md`          | OK                           |

### 1.2 search_notes 加"每文件最多 2 条"

原问题：所有命中都被 `学习Agent规划.md` 垄断（它按字母序排前，又是总览文档）。
修复：加 `MAX_PER_FILE = 2`，搜索循环里对每个文件计数。

效果对比（搜 `handoff`）：

修复前：全是 `学习Agent规划.md`。
修复后：
- 学习Agent规划.md line 37
- 学习Agent规划.md line 123
- 学习进度.md line 71
- 学习进度.md line 74
- 第5周笔记.md line 1

### 1.3 main.py 加输入层保护

`check_input`：问题超过 500 字符直接拒绝，不走模型。
理由：让 500 个 `a` 这种输入先被 Python 拦下，省 token。

### 1.4 main.py 升级为交互式循环

- 支持多轮历史，用 `result.to_input_list()` 续接；
- `/new` 清空历史；
- `/exit` 或 `/quit` 退出；
- 空行自动跳过。

关键实现：

```python
input_items = history + [{"role": "user", "content": question}]
result = await Runner.run(notes_qa_agent, input_items)
new_history = result.to_input_list()
```

**踩坑**：第 4 周学的是 `Runner.run(agent, question, history=history)`，
但当前版本 SDK 没有 `history` 关键字参数——必须把历史拼进第二个参数。
报错为 `TypeError: Runner.run() got an unexpected keyword argument 'history'`。

## 2. 边界输入测试（Day 4）

| 输入                    | 行为                   | 评价               |
| ----------------------- | ---------------------- | ------------------ |
| 空输入                  | 跳过，回到提示符       | 正确               |
| 只有空格                | 跳过                   | 正确               |
| 500 个 a                | 模型友好回绝，不调工具 | 比预期好，省 token |
| `🙂🙂🙂 第 7 周讲了什么？` | 忽略 emoji 正常作答    | 无编码问题         |

**发现**：面对无意义输入，模型不会盲目搜索，而是直接回绝。
这是一条隐性省钱路径——让模型自己判断，比强行调工具便宜。

## 3. 交互式循环验证（Day 3）

连问两轮验证历史生效：

| 轮次                        | 请求数 | 输入 | 输出 | 说明                     |
| --------------------------- | ------ | ---- | ---- | ------------------------ |
| 第 1 问"第 7 周讲了什么"    | 4      | 7423 | 1387 | 调工具搜索               |
| 第 2 问"它提到的账单是多少" | **1**  | 4162 | 454  | **未调工具**，直接用历史 |

第 2 问请求=1 是最关键的证据：Agent 从历史里拿第 1 问的结果作答。
代词"它"指代明确，无需搜索。

`/new` 之后同样的问题：

| 轮次                        | 请求数 | 输入 | 输出 | 说明     |
| --------------------------- | ------ | ---- | ---- | -------- |
| 第 4 问"它提到的账单是多少" | 4      | 6461 | 868  | 重新搜索 |

请求数从 1 变 4，确认历史已清空。

**注意**：`/new` 后模型仍然答出了账单，因为把"它"泛化理解为"笔记里"。
这不是 bug——LLM 默认倾向于猜一个合理解释，而不是反问。

## 5. 评估脚本的稳定性

M2 又踩了一次期望词坑。原期望词 `["检查时机", "前", "后"]`——
但模型这次写的是"处理**前** vs 返回**前**"，没有"后"字。

修法：换成 `["检查时机", "输入护栏", "输出护栏"]`——全是回答里必现的稳定对象名。

教训（再次印证）：**评估期望词不要猜模型的措辞，要选"语义必然出现"的词。**

## 6. 成本观察（第 10 周）

| 场景               | 请求  | 输入  | 输出 |
| ------------------ | ----- | ----- | ---- |
| 第 1 问（调工具）  | 4     | 7423  | 1387 |
| 第 2 问（用历史）  | **1** | 4162  | 454  |
| M2（期望词修改后） | 5     | 12260 | 2579 |

第 2 问只花 1 个请求——**多轮历史本身就是省钱手段**：用历史比重新搜索便宜约 3 倍。

反面：M2 改期望词后请求从 3 涨到 5，说明**同一个问题的措辞会影响成本**。
评估脚本本身也要控成本。

## 7. 我的复盘

- **最有用的一次修复**：`search_notes` 的每文件上限——
  改前模型只能拿到总览文档，改后能精确引用到"第5周笔记.md:5-7"这种正文位置；
- **最意外的发现**：交互模式第 2 问只用了 1 个请求——
  历史比重新搜索便宜很多，多轮对话不只是体验好，还更省钱；
