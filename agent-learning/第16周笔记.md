## 2. 关键设计

### 2.1 两层分离：`ParsedBlock` 只描述"原文的块"，`Chunk` 只描述"检索的块"

- `ParsedBlock`（`parsers.py`）：`text + locator + start + end`，**只把文件读成结构化段落**，不做任何切分；
- `Chunk`（`chunk.py`）：`id + source_path + doc_type + locator + start + end + text + hash`，**只描述检索单元**，不做任何解析。

收益：切分策略（粒度、重叠、合并）是第 19 周评测会反复调的参数，
解析层（读 PDF 用什么库、标题层级怎么保）将来换实现也不影响上层。
两层都不需要对方知道自己的内部规则。

### 2.2 `locator` 与 `start/end` 各管一件事

- `locator` 给**人**看：PDF 是"第 3 页"、docx/md 是"标题一 > 小标题"、txt 是"行 5-8"；
- `start/end` 给**程序**看：语义随 `doc_type` 不同，md/txt 是行号、pdf 是页码、docx 是段落号，**闭区间**。

分开的理由：locator 的格式会随场景漂移（用户要好看的、日志要好读的），
而 start/end 要严格可编程。混在一个字段里的代价，第一次改格式时就付了。

### 2.3 不变量由测试守，不靠注释守

`chunker.py` 的 docstring 写清了不变量：

1. 每个 Chunk 的 text 非空；
2. **典型长度 300~500，但短尾合并可能把它顶到 `MAX_CHARS * 1.5`（≈750）**——有意取舍；
3. Chunk 顺序与原文件一致；
4. 合并块之间以空行分隔，保留段落结构。

但注释不执行，测试执行。4 条 `test_chunker.py` 只钉**结构性判据**：
非空、长度有上界、id 唯一、碎片不乱丢。**不钉精确字符数**——
这是第 14 周 T13 的教训：钉死具体数字会让调参时到处误报。

### 2.4 短尾合并：宁可稍微超上界，也不留 3 字碎片

长文本按句切后，如果尾段只有几十字，直接留作独立 Chunk 会让检索噪声飙升。
两处合并规则：

- `_split_long` 内部：尾段 < `max_chars // 2` → 并到前一段；
- `chunk_blocks` 末尾：最后一块 < `min_chars` → 并到前一块（若合并后 ≤ `max_chars * 1.5`）。

**副作用**：单个 chunk 可能到 655 字，超出 `MAX_CHARS=500`。
这是有意的——**上界是"目标"，不是"硬约束"**。把上界钉死会逼出碎片，碎片比超一点更糟。
第 19 周做检索评测时，如果发现长 chunk 影响召回，再回来调 `max_chars`。

## 3. 踩坑

1. **测试抓到一个真 bug**：`Chunk.id = source_path:start:hash`。
   长文本按句切时，同一行的多个 chunk 会共用 `start`；如果切出的文本恰好相同
   （如"这是一句话。"重复 300 次），hash 相同 → **id 相同**。
   id 是索引主键，重复会互相覆盖。加后缀 `-1` / `-2` 去重。
   **不写 `test_chunk_blocks_multiple_chunks_have_unique_ids` 就漏了。**
2. **`test_parsers.py` 一开始放错目录**（写在 `rag/` 下）。ruff 立刻报了 import 排序问题，
   但更根本的问题是：测试文件**物理上应该在 `tests/` 下**，
   混在源码目录里迟早被误当模块 import。是 ruff 的 I001 提醒了我。
3. **`_check_size` 引用了不存在的常量**：我一开始写的是 `config.MAX_FILE_BYTES`，
   实际定义在 `tools.py`。这类"猜错引用的位置"不报 ImportError（因为 `config` 存在），
   只在运行时抛 `AttributeError`——**又是"看起来跑了、实际没跑"的变体**。
   修法：显式 import `tools`，看 `dir(tools)` 确认常量。
4. **PowerShell 上普通用户建不了文件符号链接**：`pytest -q` 会 `1 skipped`。
   切到管理员权限后 46 passed。这是平台限制，不是代码 bug；
   已在 `学习进度.md` 记一笔，第 22 周或专门一轮处理（要么检测后 skip 得干净些，
   要么用开发者模式解决）。
