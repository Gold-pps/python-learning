# 第四阶段学习规划：从"我能用"到"别人能用"（第 35~40 周）

## 〇、这一阶段要解决的问题

第三阶段结束时的状态（见 `第三阶段结项.md`）：能力齐了——检索问答、MCP 接口、核对清单、结果导出，
而且都有证据。**但整套东西还只有"我在自己电脑上跑"这一种活法**：

| 第三阶段暴露的真缺口 | 具体症状（都真发生过） |
| -------------------- | ---------------------- |
| **语料更新是手工流程** | 每次补资料要手动 `scan` → `build` → 冒烟 → **再改 4 处文档数字**；T56 已经咬了三次 |
| **使用数字没有稳定入口** | 想核 README 里的"574 条"时，日志统计脚本写了两次都对不上口径，最后只能改成"不写快照数字" |
| **只有问答题，没有可交付物** | 能力演示得很清楚，但"拿得出手的一份东西"每次都是临时做 |
| **没有部署与恢复** | 重启机器要手动三行命令；索引没有备份演练；绑定地址与口令全靠记 |

所以这一阶段的主线只有一句：**把"能跑"变成"能持续跑、别人能接手"**。

## 一、四个目标

### H1 使用数字一条命令给出来（**先做这个**，第 35 周）

为什么排第一：它是"文档会撒谎"的根——T56 反复咬人的本质是**数字靠人手抄**。

- `python -m web.usage --summary`：提问次数 / 精确引用 / 只到文件 / 编造 / 花费（按天、按峰谷分开）；
- **加一条测试**：扫描 `README.md` 与 `汇报材料-技术版.md`，出现"累计 N 条""N 篇 / N 片段"这类**裸快照**
  就红，要求带日期与口径、或给命令（把 T56 的教训变成机制，而不是靠记性）；
- 验收：README 里每一处使用数字都能用一条命令复现；那条扫描测试真有牙（故意写个裸数字它要红）。

**状态（2026-10-26，已部分落地）**：

- ✅ `uv run python -m web.usage --summary`（+ `--json`）已上线：问答次数 / 日期范围 / 引用三档 /
  无引用条目 / 硬事实待核 / 降级次数；坏行跳过并计数，日志缺失不炸；
- ✅ 两条守卫测试：① README 不许出现"累计 N 条"裸累加值；② README 的"N 篇 / M 片段"
  必须等于 `data/index/meta.json` 的 `n_files` / `n_chunks`（**没有索引时 skip**，CI 安全）；
- ✅ **它上线就抓出两处 README 与事实不符**：写"0 编造"，日志里 **37 次中有 1 条编造**；
  写"26 次真实提问"，日志实际到 **37 次（10-09 ~ 10-20）**——两处都已改准，并改成给命令复现；
- ✅ **`cost` 已落盘（2026-10-26，H1 闭环）**：`web/service.py` 写日志时把 `record["cost"] = view["cost"]`
  一起存（含峰谷标记——单价差一倍，不存就解释不了同样 token 数为什么钱不同）；
  新增测试 `tests/test_usage_cost.py`：**走真实 `ask()` 路径**写出日志，断言 `cost.usd > 0`
  且 `summarize()` 的 `no_cost == 0`。
  > 尚未回填的历史：那 37 条旧记录**天然没有 cost**（当时没写），所以 `--summary` 会显示
  > "37 条无成本记录未计入"——这是**如实**，不是 bug。想补齐只能靠当时的手记。
  **H1 到此闭环**：问答次数、引用三档、硬事实、降级、**花费**都能从日志复现。

**降级条款**：若日志字段不足以区分口径 → 先把日志写入端补齐字段（这是更该做的事），
`--summary` 只报能算准的项，其余标"口径未定"。

### H2 语料更新一条命令（第 36~37 周）

- 验收：加 1 篇 PDF → 跑一条命令 → 索引与文档同步；**故意放一个坏 PDF → 停在第 1 步并说清原因**；
- 验收（关键）：回归一次"补资料"全流程，用时从"半小时手工 + 4 处手改"降到**一条命令 + 一次确认**。

**状态（2026-10-26，已全流程真跑）**：`uv run python -m rag.refresh` 在真实语料（66 篇 / 3724 片段）上跑完：

| 步 | 实测 |

| [2/4] 建库 | 全量重算 3724 片段、退出码 0、报告写 `eval/建库报告-自动.md` |

### H3 部署与恢复演练（第 38 周）

- **语料备份 + 恢复演练**（**不是索引备份**——见下面那条"改了主意"）；
- 默认值收紧：默认只绑 `127.0.0.1`、对外必须显式给口令（现在已经是这个行为，要写成文档 + 自检项）；
- **三方数字自检**（`--check`）：`data/corpus` 篇数 / `data/index` 篇数 / 文档里写的篇数，三者对不上就非零退出；
- 验收：删掉本地 `data/corpus` → 从备份恢复 → `--check` 通过。

> **改了主意（2026-10-26）：不做开机自启。**
> 原计划里写的是"开机自启 + 索引备份"，复盘时发现两处都错：
> ① **自启的收益抵不上风险**——常驻监听（绑 `0.0.0.0` 就可能被同网段试口令）、
> 端口/版本混乱（"自动拉起的那个"和"我刚改完重启的那个"分不清）、排障要多判断一层；
> 而这个项目一个多月只用过 37 次，**手动三行命令的代价远小于常驻风险**。
> ② **该备份的不是索引**：`data/index` 是 3 分钟可重建的派生物（实测 3724 片段、退出码 0），
> 而 **`data/corpus/` 那 66 篇 PDF 既不在 Git（`data/` 在 `.gitignore`）也没有任何备份**——
> 那才是唯一不可替代的资产。
> 所以 H3 改成：**备份语料 + 恢复演练 + 三方数字自检 + 手动启动写进 README 首屏**。

**降级条款**：备份用系统自带压缩工具即可（不必自己写增量方案），只要**恢复演练真做过一次**。

**状态（2026-10-26，已完成并真跑）**：`rag/backup.py`（`--check` / `--backup`），4 条测试（含"空语料不许假装备份成功"）。

| 事 | 实测 |
| -- | ---- |
| 三方自检 | `语料 66 篇｜索引 66 篇 / 3724 片段｜索引可用 True` → **一致** ✓ |
| 语料备份 | `data/backup/corpus-20261026-141812.zip`（**159.5MB**，66 篇） |
| **恢复演练** | 解压到独立目录 → 恢复 **66 篇** = 原始 66 篇，**一致** ✓（子目录结构保留） |
| README 首屏 | 补了"手动三步启动"+ **为什么刻意不做自启** + 备份/恢复两行 |

> 踩到的坑：`--check` 第一次跑直接 `UnicodeEncodeError`（`✓`/`✗` 在 GBK 控制台印不出来，台账 T23 老坑）——
> 用仓库自己的 `make_stdout_forgiving()` 兜住，与其它 CLI 保持一致。

### H4 一份可交付的"资料综述包"（第 39 周）

- 用现成能力产出 3~5 个主题的综述包：每主题一份**带引用的四段式** + 导出 Markdown + 核对清单；
- 验收：≥3 个主题、每条结论有引用、导出文件能直接看、**抽取 5 条做核对并记录判定**；
- 代价：约 **0.2~0.3 元**（5 题 × 约 6 分），须先点头。

**状态（2026-10-26，已完成）**：跑了 **5 个主题**（刀具磨损监测 / 机床误差补偿 / AI 辅助工艺编制 /
NC 代码生成与校验 / 数字孪生与智能车间，覆盖新补的两类），实测 **$0.0319 ≈ 0.23 元**。

| 项 | 实测 |
| -- | ---- |
| 结论 | **79 条**（16+16+16+16+15） |
| 引用校验 | **89 条精确 / 0 只到文件 / 0 编造 / 0 无引用条目** |
| 交付物 | `notes-qa/eval/资料综述包.md`（目录 + 成本 + 每主题四段式 + **抽查 5 条**） |
| 逐条核对材料 | `notes-qa/eval/综述包-0N-*.md`（每条结论旁摆着它引用的原文）+ 同名 `.json`（重导出不花钱） |
| 抽查 5 条 | 机器判定"硬事实在哪"（同页另一段 / 别的候选 / 候选里都没有），**结论对错仍待人确认** |

> 复用而非新写：正文直接调 `web.service.render_view_markdown`——**与界面、导出的那份同源**，
> 所以"综述包里读到的"就是"界面上看到的"。

## 二、验收总门槛（每周都要满足，不是最后补）

- `pytest` 全绿、`ruff` 全绿、**CI 每次 push 通过**（本地有 `data/`、CI 没有——T51/T54 的教训）；
- 每条技术债进台账（现象 → 根因 → 改法 → 验证 → 影响面）；
- **"实验口径 ≠ 生产口径"**：任何"接入生产"的改动，都要在生产口径上再量一次（T57）。

## 三、明确不做（写下来是为了不被"顺便"带进去）

| 不做 | 为什么 |
| ---- | ------ |
| 多用户权限体系 | 现在只有 1~2 个使用者；先把"能持续跑"做好，别提前造组织级功能 |
| 模型微调 / 换更大的模型 | 瓶颈不在模型生成质量，而在语料覆盖与核对流程 |
| **自动判定结论的专业正确性** | 这是本项目的**边界**：只能靠领域内的人。任何"自动判定"都是把风险藏起来 |
| 把项目做成 SaaS / 对外服务 | 语料是本地论文，涉版权与隐私；保持"本机/局域网"形态是刻意选择 |
