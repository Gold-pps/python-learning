## 一句话结论

本周把系统从命令行搬进浏览器：**FastAPI + 单页前端 + SSE 进度流**，
核心算法层（`rag/review_qa.py`）**一行没改**——计时、进度、成本全靠它现成的注入点接上去。

真正值钱的东西不是"跑起来了"，而是**跑起来之后暴露的七个缺陷**。
它们全属同一个类型：**离线测试全绿，真实使用第一步就出错**。四条可迁移的结论：

1. **"协议测过了"不等于"界面画出来了"**：SSE 事件序列在离线冒烟里验过，
   而界面上进度条压根没渲染——`<li>` 只塞进了 Map，没 `appendChild` 到 DOM（T37）；
   修它的时候又把函数签名改了、调用处漏改，界面直接甩出 `TypeError`（T39）。
   **同一块功能连续两次坏在"画出来"这一步**，说明缺的不是"更小心"，而是一层不依赖浏览器的 DOM 测试；
2. **判据不能拿"长度"当特征**：追问判据两轮都栽在这里——第一版按"句子短"判，
   把「异星工厂是什么」误当追问（T38）；收紧后又漏掉同样 7 个字的
   「优缺点有哪些？」（T42）。**分得开这两句话的不是长度，是"有没有自己的主语"**——
   又一次撞上 T31/T36 那条老教训：特征要挑"目标里几乎不会出现、噪声里才有的"；
3. **界面说的必须和实际做的一致**：横幅打"本次检索词带上了上一问"，而日志里那两条
   `"question": "优缺点有哪些？"` 明摆着**没拼**（T41）。用户会因此错判
   "检索明明带了上下文，答案为什么还跑偏"，从而去改错的地方；
4. **假数据会掩盖真字段的缺失**：前端冒烟里我手写了 `doc_type: "pdf"`，
   而真实数据（`SearchHit.to_dict()`）**根本没有这个字段**，于是 PDF 被标成"行/段 4~4"（T43）。
   测试全绿、真数据一跑就露。

还有一条不算缺陷但同样该记的：**文档与提示里的示例会被原样照抄**。
我给的口令示例是中文占位符"自己定一个口令"，使用者照抄之后——
HTTP 头按 ISO-8859-1 传，浏览器**在构造请求前**就抛错，请求根本没发出去（T40）。
**这个坑是我用示例挖的。**

## 2. 关键设计

### 2.1 为什么是"阶段级进度流"，不是 token 级流式

规划原文写的是"`/ask` 支持流式返回"。落地时换成了**阶段级事件**：

```text
start → load（首次加载模型）→ retrieve（第 N 轮 / 命中几条 / 耗时）
      → plan（盘点缺口）→ answer（组织四段式）→ result（完整视图）
```

理由：`answer_review()` 的产物是**四段式 JSON**。token 级流式要么放弃 JSON 约束、
要么边流边猜结构——第 21 周刚立起来的"引用校验拿候选集合对账"会直接失效。
而一次问答要等 20~40 秒，**"知道它在干什么"比"看到字一个个蹦出来"更有用**。
这个偏离已征得使用者同意，记在台账第 23 周小节。

### 2.2 复用注入点：核心模块一行没改

`answer_review(plan_call=..., answer_call=...)` 本来就是为测试留的注入点，
Web 层直接用上了：包装一层 `_wrap_call()` 记耗时、发进度事件，
再把 `elapsed_s` 塞进 usage 字典——`ReviewResult.calls` 里那句
`dict(usage, stage=...)` 是浅拷贝，多出来的键会**原样带过去**。
（这一点是打开源码确认的，不是猜的——T3 那条"别猜第三方库的数据结构"的教训。）

检索侧同理：`TimingRetriever` 是个纯代理，只补"第几轮、命中几条、花了多久"。

### 2.3 引用可点开看原文：三种状态都要说清

答案里每条引用都是可点的标签，按对账结果分三档展示：

| 档 | 界面表现 | 依据 |
| -- | -------- | ---- |
| 精确 | 展开该片段的**原文全文**（不只是提示词里的 600 字截断版）+ 文件/位置/召回通道/融合分/稠密与稀疏排名 | `文件:位置` 与候选集合完全一致 |
| 只到文件 | 虚线边框，列出该文件本次命中的片段供人工核对 | 模型只给了文件名 |
| 回查不到 | 红底 + 明说"回查不到原文" | 不在模型看到的候选里（正常情况下走不到这条分支，留着是因为它**比静默删掉诚实**，T28 的教训） |

归一化直接复用 `review_qa._canon`——**故意不抄第二份**：
"什么算同一条引用"必须与校验完全同源，否则会出现"校验说没问题、界面却点不开"。

### 2.4 成本口径：缓存命中必须拆开算

界面上是**估算**（价格快照 2026-09-10，峰谷按时点自动换档）：

- 缓存命中价只有未命中的约 **1/50**（$0.003 vs $0.15）。拿 `prompt_tokens` 直接乘输入单价
  会把成本**高估 8 倍以上**——而这个方向的误差是有害的：它会让人以为"这系统很贵"而不敢用；
- 判断峰谷必须用**北京时间**，不能信本机本地时间（这台机器恰好 +08:00，换台机器就不成立）；
- `cached_tokens` 会被夹在 `[0, prompt_tokens]` 之间：上游偶发给出不一致的数时，
  宁可少算，也不要算出负数。

### 2.5 口令与默认边界

规划里写"不做多用户鉴权"，照做；但**默认只绑 `127.0.0.1`**，
`--host` 非回环时**必须**同时给 `--token`，否则拒绝启动——不是警告，是拒绝。
理由很实际：这个服务会花你的额度调模型，绑到 `0.0.0.0` 又不设口令，
等于同网段任何人（以及他电脑上的任何脚本）都能拿你的 Key 提问。

口令**只允许可见 ASCII**（T40 的产物）。这条不是洁癖：HTTP 头按 ISO-8859-1 传，
中文口令会让浏览器直接拒绝发送请求，而服务端那侧同样对不上（ASGI 按 latin-1 解码头部字节）。
两头都对不上，所以别让它进系统。

### 2.6 追问判据：三版演进

```text
v1  "长度 ≤ 12 或含指代词"          → 误伤：「异星工厂是什么」（短）被当追问，检索被带偏（T38）
v2  "指代词 / 追问标记词 / ≤6 字"    → 漏判：「优缺点有哪些？」（7 字）没带上文（T42）
v3  v2 + "以相对属性词开头且 ≤12 字" → 该带的带上（复跑已验），代价是仍会误伤
```

「优缺点有哪些？」与「异星工厂是什么」**都是 7 个字**——长度分不开它们。
分得开的是"这句话有没有自己的主语"：前者问的是"上面那个东西的属性"，
后者自带新主语。判据仍是启发式，**所以界面必须显示"实际检索词"**——
判错的成本被可解释性兜住了（T41 修的就是这条配套）。

### 3.3 跨机与并发

| 检查 | 结果 |
| ---- | ---- |
| 网段 | Windows `10.5.111.131`；Linux `10.7.35.108/18`（子网 10.7.0.0~10.7.63.255）——**不在同一 /18** |
| Windows → Linux ping | 4/4 通、平均 5ms、TTL=63（过了一跳路由器，印证跨子网） |
| Linux → 服务 | uvicorn 日志里出现 `10.7.35.108:45618 - "GET /api/health HTTP/1.1" 200 OK`：跨子网路由通、**Windows 防火墙没挡、也不需要加规则** |
| 会话隔离 | 两个浏览器同时追问「优缺点有哪些？」——各自带的是**各自**的上一问，没有串 |
| 冷启动 | 首次提问"正在把检索模型读进内存"，检索 3.32s；此后每次 0.01~0.02s |

排查过程本身也值得记：第一次 `curl` 超时的真实原因是**服务没在跑**（`netstat` 无输出），
不是网络问题。所以诊断顺序必须是"先确认服务在听，再怀疑网络"——
顺手把启动横幅改了：绑 `0.0.0.0` 时**打印真实的局域网地址**（原来打印 `http://0.0.0.0:8000`，
那不是能打开的地址），并把三步排查顺序印出来。

## 4. 踩的坑：一周七个，分三类

| 类别 | 条目 | 一句话 |
| ---- | ---- | ------ |
| **展示层与事实脱钩** | T37 / T39 / T41 / T43 | 进度条没画出来；改签名漏改调用处；横幅说了没做的事；PDF 被标成"行/段" |
| **判据挑错了特征** | T38 / T42 | 两次都以为"句子短 = 追问"，两次都被同样 7 个字的反例打脸 |
| **配置与示例** | T40 | 中文口令让请求发不出去——**坑是示例里那个中文占位符挖的** |

共同点很硬：**离线测试全绿**。T37/T39 是 DOM 完全没测；T38/T42 是启发式的反例不在测试里；
T40 那条代码路径在单机下根本走不到（`auth=false`，前端从不设那个头）；
T43 是**假数据挑对了字段、真数据没有它**。

所以本周真正的技术产出不是界面，而是这条认识：
**"做完了"和"用过了"之间隔着一整类 bug，而它们的共同特征是不会让任何既有测试变红。**

## 5. 我的复盘

### 5.1 四条可以带走的

1. **先把"观测面"建起来，再谈优化**：界面上的耗时/成本/检索词/引用分档，
   一开始像是"锦上添花"，后来每一条排查都靠它们。T41 甚至就是"观测面本身在撒谎"
   被观测面自己暴露出来的；
2. **判据的错，比判据的漏更贵**：T38 的误判把检索带偏了整轮，T42 的漏判让答案散成三摊。
   两次都不是"效果差一点"，而是**答案跑到了另一个主题上**。判据要拿真实反例反复撞，
   撞不动才算过——这正是"长度"这种顺手特征最危险的地方；
3. **测试夹具要尽量从真数据派生**：T43 的根源是我在夹具里手写了字段。
   下一步值得做成"从一次真实检索结果导出夹具"，让"真数据长什么样"这件事自动化；
4. **示例是接口的一部分**：T40 不是使用者操作失误，是我给的示例不能用。
   凡是会被原样照抄的字符串（口令、URL、路径、命令），都得是能跑通的值。
