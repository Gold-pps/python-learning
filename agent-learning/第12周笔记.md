## 3. 最有价值的三件事

### 3.1 每周一个可运行产出

不只看文档。12 周里除了第 12 周（整理周），每周都有能跑的东西。
这个节奏保证"学的每一周都落地"。

### 3.2 让 Agent 审查自己的项目

第 11 周让 Codex 审查 notes-qa，发现两个真 bug（junction 逃逸、truncated 语义）
和一堆加固点。这个模式很值：**人写代码 → Agent 审查 → 人工判断**。

### 3.3 评估脚本本身也要评估

第 9~11 周反复踩"评估假阴性/假阳性"的坑。经验：

- 期望词选"语义必然出现"的稳定词，不猜模型措辞；
- 匹配前先归一化（去 Markdown 符号、去空白）；
- 报 FAIL 时先判断是真失败还是匹配太窄。
