# 第 4 周笔记：为什么要传 history

日期：2026-09-08

## 结论

Agent 和模型本身没有记忆。每次 `Runner.run` 都是一次独立的调用，
模型只“看得到”这次请求里传进去的内容。想要它记得上一轮的信息，
必须把之前的问答一起放进 history 再发过去。

## 三种续接方式的区别

| 方式 | 历史存在哪里 | 说明 |
| --- | --- | --- |
| 手动传 history | 自己的程序里 | 每次用 `result.to_input_list()` 取出完整历史，拼上新问题再发送 |
| SDK Session | 自己提供的本地存储 | SDK 自动读写同一份历史，适合持久化场景 |
| 服务端 continuation | OpenAI 服务器 | 只适合 OpenAI 模型；DeepSeek 无法管理这份状态，不能使用 |

## 对照实验记录

同一个人物信息（张伟、机械设计制造及其自动化、《深度学习入门》），
分别用“传 history”和“不传 history”运行：

带历史（`03_multiturn_memory.py`）：

```text
问：请记住：我叫张伟，专业是机械设计制造及其自动化，最近在读《深度学习入门》。
答：ok

问：我叫什么名字？     答：张伟。
问：我的专业是什么？   答：机械设计制造及其自动化。
问：我最近在读哪本书？ 答：《深度学习入门》。
```

不带历史（`03_no_history_test.py`）：

```text
问：请记住：我叫张伟，专业是机械设计制造及其自动化，最近在读《深度学习入门》。
答：ok

问：我叫什么名字？     答：我不知道。
问：我的专业是什么？   答：不知道。
问：我最近在读哪本书？ 答：不知道。
```

## 一句话总结

模型不会自动记得，只有把 history 一起传过去，它才知道你之前说过什么。
