## 0. 一页结论

**是什么**：一个跑在本机的资料问答系统。把 44 篇数控 / 智能制造方向的论文建成索引，
用自然语言提问，输出**四段式**（研究现状 / 方法对比 / 结论 / 可复用点）答案，
**每条结论挂 `[文件:页码]` 引用**，资料里没有的会明说"资料中没有"。

**三个数字**

| 指标 | 数值 | 怎么算的 |
| ---- | ---- | -------- |
| 引用可信度 | 真实使用 50 条引用 **0 编造** | 代码拿候选集合逐条对账（三档：精确 / 缺定位 / 编造） |
| 引用可回查 | 抽查 **9 条**（4 + 5）逐字对得上 | 从索引里取出被引用页原文，人工逐字比对 |
| 检索收益 | 有答案类 Recall@5：**重排 12/20 vs 关键词基线 1/20** | 25 条评测集，Top-5 严格判据 |

**三条局限（先说清楚）**

1. **能力边界在语料上，不在模型上**：本库覆盖"加工机理 + 监测/优化/仿真/补偿"，
   **不覆盖"AI 辅助工艺编制 + NC 代码工程"**——问大模型如何辅助工艺编制、怎么写 NC 代码检查，
   本库答不了（实测：相关关键词在语料里命中 **0 片段**）；
2. **表格与公式的结构会丢**：PDF 解析把表格拍平成一串数字，引用数值时必须回原文核对；
3. **"引用可回查"不等于"能直接用"**：实测发现三处语境漂移（超精密慢刀伺服的参数被当成常规车削、
   转引他文的结果、RL 智能体与 LLM 智能体同词不同义）。这类问题机器只能提示，最终要人读。

**一句话自我介绍（诚实版）**：
> "它能把你手头那批论文里'这个方向有哪些方法、各自优缺点'整理成带出处的四段式答案；
> 它不会编引用，但**你仍然要读关键条目**——它对'数值能不能直接拿去用'这件事不负责任。"

## 1. 现在能做什么

**输入**：一句自然语言问题（中文 / 英文），可带 `/deep` 前缀表示"这题值得多想"。

**输出**（每次一个 Markdown 报告 + 一行机读日志）：

- 四段式结构化答案，每条结论带 `[文件:页码]`；
- `insufficient` + `note`：资料撑不起某一段时明说"资料中没有……"；
- 引用校验结果：精确 / 缺定位 / **编造** 三档计数（编造必须为 0）；
- 候选清单（人工核对用）、每次调用的 token 与耗时。

**命令**（在 `agent-learning/notes-qa` 下，PowerShell）：

```powershell
uv run python -m rag.review_qa --query "刀具磨损监测有哪些主流方法？各自的优缺点是什么？" --out eval\报告.md --log data\usage_log.jsonl
```

**真实使用的一次输出（摘要，第 22 周第 1 题）**：
问"刀具磨损监测与换刀决策"，答案给出直接法/间接法分类、力传感器与电流传感器的优缺点
（"可靠性高但价格高不易安装" / "经济便于安装但灵敏度弱、更适合破损监测"）、
以及落地限制（传感器成本与安装、失效阈值制定、复杂工况适用性）——17 条引用全部精确可回查，
它同时声明"缺少车间落地的定量效益数据"。

**不适合用它做的事**（避免误用）：生成 NC 程序、做工艺方案编制决策、
把答案里的数值直接代入生产参数、替代人工审核。

## 2. 系统怎么工作（8 步链路）

```text
① 解析      PDF / Word / Markdown → 文本 + 页码        pypdf / python-docx
② 切分      300~500 字/片、重叠 50 字                  rag/chunker.py
③ 向量化    BAAI/bge-small-zh-v1.5（ONNX，CPU）         rag/embedder.py
④ 索引      chunks.jsonl + vectors.npz + meta.json      rag/index.py（支持增量）
⑤ 检索      BM25 稀疏 + 向量稠密 → RRF 融合             rag/retriever.py
⑥ 重排      模型把 top20 压到 top5（可选，只在需要时）   rag/rerank.py
⑦ 综述生成  「盘点 → 补检 ≤1 轮 → 组织」两次调用        rag/review_qa.py
⑧ 引用校验  拿候选集合对账，三档计数                    rag/review_qa.py
```

每一步的技术选择与代价（被追问时讲这个）：

| 步骤 | 选择 | 为什么 | 代价 |
| ---- | ---- | ------ | ---- |
| ③ 向量 | 本地小模型 + ONNX + CPU | 小批量下比 torch+CUDA **更快**（实测冷启动 0.33s vs 13.08s，因为 CUDA 上下文要十几秒）；不用外网、不花钱 | 超大语料批量时 GPU 才划算 |
| ④ 索引 | 三个文件（jsonl + npz + json） | 30~300 篇规模用不上向量数据库；落盘可直接 diff、可人工看 | 上到万级片段要换方案 |
| ⑤ 融合 | RRF 按**排名**融合 | BM25 分数无上界可为负、余弦在 [-1,1]，量纲不可比；排名天然免疫 | 会"偏爱两路都召回"（实测过它的副作用） |
| ⑥ 重排 | 只在"分不开"时调模型 | 重排是花钱的，融合本身有把握时不该花 | 现行触发条件在 RRF 上失效（已登记待改） |
| ⑦ 生成 | 代码驱动两调用流水线 | SDK 工具循环里"模型自己决定检索几轮"→ **成本不设上限**；JSON 约束与引用对账也要代码级控制 | 少了"模型自由发挥"的灵活性 |
| ⑧ 校验 | 三档分类，不删只记账 | "模型没给引用"是要报告的事实，不是要替它抹平的瑕疵 | 需要人读一眼 |

## 4. 局限（先说清楚，再讲能力）

### 4.1 能力边界（语料层）——**最重要的一条**

实验室方案里想要的模块 vs 本库覆盖：

| 方案模块 | 语料覆盖 | 结论 |
| -------- | -------- | ---- |
| 大模型与智能体辅助（工艺知识整理、相似案例检索） | 关键词 **0 片段** | ❌ 本库支撑不了 |
| NC 程序检查（语法 / 模态 / 安全点） | **0 / 0** | ❌ |
| 案例检索（"相似案例"） | **0 / 0** | ❌ |
| 工艺知识 / 知识图谱 / 工艺设计 | 3 / 4 / 4 片段（1~3 篇） | ⚠️ 极薄 |
| 后处理 | **1 片段 / 1 篇** | ⚠️ |
| 仿真 / 数字孪生 | 229 / 288 片段 | ✅ 但偏**车间级**，不是几何级刀轨碰撞验证 |
| 磨损 / 热误差 / 切削力 / 参数优化 | 382 / 148 / 132 / 65 片段 | ✅ |

**要支撑"AI + 智能制造实验室"的方案，第二期至少补四类资料**：
① LLM/Agent 在工艺设计与 CAPP 中的应用；② NC 程序检查与后处理；
③ 车削工艺与刀具（**本库以铣削为主**，`车削` 仅 63 片段/15 篇）；
④ 几何级刀轨与碰撞验证仿真。

### 4.2 已知技术缺陷

| 缺陷 | 影响 | 现状 |
| ---- | ---- | ---- |
| 表格 / 公式被拍平 | 引用数值会指向"一串数字" | 接受（pypdf 限制）；要数值就走 Vision 支线（花 token） |
| 2 篇文字层缺 ToUnicode | 片段不可读 | 已标注 + **检索层排除**（实测排除 23 条 = 18+5） |
| 参考文献列表页抢分 | 对任何查询都"语义相近" | 已标记 **657/2501** 并从候选排除（含页级表决） |
| 答案可能"拿错语境" | 数值/方法看似可用实则不适用 | 提示词已加"语境保真"两条；**效果待下轮真实使用验证** |
| 转引他文的结果 | 出处对、归属错 | 已登记（需在答案里保留"某某等提出"） |
| 术语同词不同义 | 如"智能体"= RL agent ≠ LLM agent | 提示词要求显式说明差异 |

### 4.3 自评的边界（这条最容易被忽略）

- **引用校验只能保证"没编造"**：它拿候选集合对账，挡不住"引用是对的、结论被误用"；
- **判据本身也会错**：第 22 周参考文献段判据第一版把 **26.6% 的正文页**标成了文献表
  （测试全绿，因为测试只验证"该标的标了"，没验证"不该标的没标"）；
- 所以流程是**两道**：代码校验 + 人读关键条目。汇报里不该只讲前者。

### 4.4 我犯过的三个错（讲出来比藏着更有说服力）

| 事故 | 现象 | 教训 |
| ---- | ---- | ---- |
| 输出预算 4096 | 四段式答案 3/3 被截断（一题连答案都没开始写） | 预算 = **产物长度 + 模型思考长度**；上限贴着实测值等于没给 |
| 评测判据第一版 | 只允许一个"正确答案文件"，把台账/进度里的正确记录判成错 | **判据改了就必须重跑**，否则分数没有意义 |
| 参考文献段判据第一版 | 26.6% 正文页被误标 | 判据的特征要挑"目标里几乎不会出现、噪声里才有的" |

## 5. 被追问时的口径（Q&A）

**Q：为什么不用向量数据库（Milvus / Chroma / pgvector）？**
A：规模不匹配。2501 条片段的向量是 2501×512 的矩阵，点积全量算一次是毫秒级；
索引落成 `vectors.npz` + `chunks.jsonl`，可以直接 diff、可以人工打开看。
换规模的触发点写在这儿：**上到 10 万条片段**或需要按元数据做复杂过滤时再换。

**Q：为什么不用 LangChain / LlamaIndex 现成的 RAG 链？**
A：这段学习的目标就是把每一层（解析 / 切分 / 向量化 / 融合 / 重排 / 引用校验）自己写一遍，
知道每一步在做什么、坏在哪里。框架能省事，但省掉的正是我想学的部分。
代价是生态、预置能力都要自己补——比如重排、引用对账这些框架里也未必有。

**Q：为什么答案是"四段式"而不是一段自然语言？**
A：这是使用场景定的：工艺/研究人员要的是"有哪些方法、各自优缺点、哪些能复用"，
而不是散文。四段固定键名 + JSON 输出让结构稳定、可程序化消费（后面接界面、接表格都好办）。

**Q：怎么保证引用不是编的？**
A：三件事叠加：① 提示词要求引用必须原样取自候选；② **代码拿候选集合对账**——
文件不在候选里的引用会被单独记账（编造数必须为 0，实测 105 条引用 0 编造）；
③ 人工抽读 + 回查脚本（从索引里取被引用页原文逐字比对，已查 9 条）。
但**这不保证"用对了"**——见 4.3。

**Q：为什么每篇论文最多只取 2 条片段？**
A：实测一篇综述能同时命中小节标题与正文，把 top-5 全占满，答案会退化成"复述一篇"。
加上限后"不同论文数"从 2~4 篇提升到 3~4 篇。

**Q：检索效果为什么"混合+重排"才达标？**
A：纯 BM25 打不过关键词基线之外的语义问题，纯向量漏精确术语；RRF 把两路合起来，
重排再按"是否真的相关"排一次。数据见 3.2——重排把有答案类从 5/10 提到 8/10。

**Q：成本怎么控？会不会调用失控？**
A：一次问答**最多 2 次模型调用**（这是硬上限，写在代码里，不靠模型自觉）；
候选 10 条、单条 600 字；输出有额度与"每段 ≤4 条"的双重约束；
真实使用三次合计不到一分钱。

**Q：数据安全？语料会不会外传？**
A：索引与日志都在本地 `data/`（不进 Git）；语料是使用者自备的论文，**不随仓库分发**；
只有"提问 + 候选片段"会发给模型服务，且这一问题在项目启动时就写进了档案。

**Q：换一批语料要重做哪些事？**
A：`index scan` 预检（失败/空文档/文字层可疑三个清单）→ `build --all --verify --report`。
注意：**评测数字不能跨语料比较**，换语料后要重测（这条踩过坑，已写进进度文档）。

**Q：为什么不直接用大模型写 NC 代码？**
A：方案里明确"一期不纳入"（任意机床适配、无专家参与的自动工艺决策、完全由大模型计算刀轨等）。
从我们这边看也一致：**大模型不擅长可验证性强的硬约束**，而刀轨/碰撞这类问题恰恰要求可验证。
