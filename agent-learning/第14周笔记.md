## 2. 关键实现

### 2.1 清理责任不该写在测试自己身上

旧评估脚本把探针文件建在仓库根，靠手写 `finally` 删。第 13 周 T2 的 bug（`os.rmdir` 删符号链接失败、
异常又被 `except OSError: pass` 吞掉）就是这套做法的必然结果：**测试全绿 + 仓库变脏**。

迁移到 pytest 后，`conftest.py` 的 `notes_root` fixture 把 `config.NOTES_ROOT` 换到 `tmp_path`，
清理责任交给 pytest。新测试里**一个 `finally` 都没有**——那类 bug 在结构上不可能再发生。
附带收益：套件从 ~5 秒降到 0.15 秒（旧入口每次都扫真实仓库）。

### 2.2 能力指标与遵从性指标必须分开

首跑有两条 FAIL，看起来是"没找到出处"，实际是模型把引用写成了反引号 `` `文件.md:行号` ``
而不是约定的 `[文件:行号]`。原来的判据把两件事混在一条断言里，于是**格式不合规被记成了能力不足**。

改法：`extract_cited_files()` 两种写法都认（判断"引用内容对不对"），另加
`require_bracket_citation` 单独统计**格式合规率**。现在跑完会多打一行：

```text
引用格式合规：8/8（与上面的通过率是两件事：内容对、格式漂移也会记不合规）
```

### 2.3 一处过滤规则、一份接入配置

- `tools.py` 的 `_iter_notes()`：把"排除目录 + 隐藏文件 + 链接逃逸"三条安全过滤收成一份。
  抄两份的代价在第 10 周就付过了——修 `read_note` 的排除目录漏洞时，`search_notes` 得单独再修一次；
- `_common.py`：8 个周脚本各抄一遍的 DeepSeek 接入样板（读 `.env` → 取密钥 → 建客户端 → 三步设置）
  收成一份，模型名从 12 处硬编码收敛到 `MODEL` 一个常量。

### 2.4 ruff：先圈范围，再谈"全绿"

直接跑 `ruff check .` 报 51 个问题——但那是假象：仓库里没有配置，于是把 `python-base/`
（`AGENTS.md` 写明"暂未整理"）和仓库根那堆 PPT 工具全算了进来。建 `ruff.toml` 圈定
`agent-learning/**/*.py` 之后，真正要处理的是 33 个，其中 28 个自动可修，**只有 5 个需要动脑**。

规则集用**默认**，不 `select = ["ALL"]`：后者会给出几百条风格意见，结局通常是把配置整个关掉。

### 3.3 交叉验证：用变异测试而不是目测映射表

把 `notes-qa/` 复制到临时目录，故意改坏一个行为，看两条入口是否都报警：

| 变异 | pytest | `--unit-only` | 结论 |
| --- | --- | --- | --- |
| `read_note` 大小检查放宽 100 倍 | 1 failed | 11/12 | 一致 |
| 去掉越界拦截 | 3 failed | 9/12 | 一致 |
| 去掉排除目录 / 隐藏文件过滤 | 1 failed | 11/12 | 一致 |
| `MAX_READ_LINES` 200 → 199 | 全绿 | 12/12 | **两条都漏** |

第四行是真发现：两个套件的边界用例都写成 `assert end_line == tools.MAX_READ_LINES`，
**拿常量跟自己比**。调参时是优点，常量被误改时是盲区。补法是另加
`tests/test_documented_limits.py` 只钉**文档承诺过**的四个数字（1MB / 200 行 / 5 条 / 500 字符），
并确立原则：**钉文档承诺值，不钉明确待调的初值**（如 T3 的 `MAX_HISTORY_TURNS`）。

### 3.4 成本

本轮 10 条评估 39.3 万 token、67 次请求，按低谷价粗估 **约 0.25~0.3 元**
（精确值以平台账单页为准；`--save` 的 JSON 里有逐条用量）。

两个值得记住的观察：

1. **通过率和成本是两个独立维度**：9-18 那次 8/10 用了 21.7 万 token，
   这次 10/10 用了 39.3 万——多出来的钱花在"多跑了几轮工具"上
   （请求数 49 → 67，最贵的 D2 一条就 12 次请求、10.6 万输入 token）。
   第 19 周做对比表时必须**同时记录通过率与成本**，否则"更准"可能只是"更贵"；
2. `07_evaluate_agents.py` **没有打印 token 用量**（它靠 subprocess 跑别的脚本），
   所以那 3 条用例的成本这次没记上——属于记账口径的漏洞，排进待办。

## 4. 踩坑

1. **fixture 依赖链不显式，`monkeypatch` 就静默失效**：`make_file_link` 忘了依赖 `notes_root`，
   于是探针被建到**真实仓库**里（`agent-learning/逃逸链接.md`）。更阴的是只有个别用例中招——
   同时用了 `write`（它依赖 `notes_root`）的用例因为别人的依赖链"碰巧"正确。
   修法：显式依赖 + `assert link.is_relative_to(tmp_path)`。
2. **`git checkout --` 会连别的改动一起冲掉**：为验证泄漏检查，我往 `学习进度.md` 追加了一行，
   用 `git checkout --` 还原时把该文件**所有未提交改动**都抹了。它不报错，看起来像"清理干净了"。
   清临时改动要用 `apply_patch`。
3. **题库会污染资料库**：把"无答案"题的负样本关键词写进 `agent-learning/*.md`，
   等于把答案卡交给被检索的 Agent（模型直接引用我写的那句话证明"资料里没有"）。
   规则：负样本关键词只写在 `notes-qa/` 内（已在 `EXCLUDE_DIRS` 中），并加测试守住。
4. **`ruff --fix` 会删掉写法不规范的 noqa**：`# noqa: BLE001 —— 说明文字` 被判为无效指令删掉。
   noqa 必须规范收尾，说明另起一行。**`--fix` 之后必须重跑检查**。
5. **"51 个 ruff 错误"是个假象**：没说清范围之前，任何"多少个错误"都没有意义。
6. **旧入口会把文件内容整段打进 FAIL 行**：跑变异测试时输出爆了 26 万 token。
   验证类脚本的输出要限流（`cut -c1-100`），否则日志本身成为负担。
7. **`--save` 的文件要记得 gitignore**：`eval_last_run.json` 有 25KB，落仓就是新的垃圾。
