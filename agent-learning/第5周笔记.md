# 第 5 周笔记：多 Agent 编排与交接（handoffs）

日期：2026-09-08

## 结论

当问题需要某个“专长 Agent”直接接管后续回答时，用 handoffs；
当总控只是借用另一个 Agent 的结果、自己继续说话时，用 Agent as tool。
本 Demo 采用 handoffs：总控分流后退出，由专长 Agent 完成回答。

## 结构

```text
triage_agent（总控/分流）
  ├── history_teacher（历史老师）
  └── math_teacher（数学老师）
```

总控通过 `handoffs=[history_teacher, math_teacher]` 声明可以交接给谁；
运行时由模型根据指令和 `handoff_description` 决定交接对象。
运行结束后用 `result.last_agent.name` 查看最终接管回答的 Agent。

## 验证输出

```text
问：明朝是哪一年建立的？
实际回答的 Agent： history_teacher
答：1368 年，朱元璋在应天府称帝。

问：小明有 7 个苹果，又买了 5 个，再吃掉 3 个，还剩几个？
实际回答的 Agent： math_teacher
答：9 个。

问：How are you 怎么翻译？
实际回答的 Agent： triage_agent
答：总控说明自己只管历史/数学，不硬答翻译问题。
```

## 踩坑记录

交接会生成类似 `transfer_to_<agent_name>` 的隐藏工具，
只支持英文字母、数字和下划线。Agent 名字用中文（如“历史老师”）
会被转义成相同的名字并冲突，导致部分交接失败。
因此 Agent 的 `name` 应使用英文标识，中文说明放在
`handoff_description` 和 `instructions` 里。
