# 第三阶段中期复盘（第 26~34 周，写于 2026-10-21）

## 〇、先说清：为什么这一篇合并了九周

每一周的规矩是**当周写一篇笔记**，前面 23 周都是这么过来的。第 26~34 周没有逐周补，理由不是懒，
而是**补不出来**：那段时间的工作几乎全是"撞坑 → 定位 → 修 → 记台账"的循环，
真实记录已经以**台账条目**（T44~T53）和**验收材料**（H2/H3 的真跑记录、建库报告、核对清单）的形式存在。
隔了这么久回头编九篇"本周我学到了什么"，编出来的只会是排比句，不是记录。

所以这篇按**目标**组织（H1~H4），每段都挂证据出处。**读这篇的人应该能顺着链接查到原始材料**，
而不是只能信我的转述。

## 二、H2「把能力做成标准接口」：三个工具 + 真接两个客户端

`notes-qa/mcp_server/`，`mcp 2.2.0`（`FastMCP` 已改名 `MCPServer`，网上教程照抄会报错）：

| 工具 | 花钱 | 协议注解 |
| ---- | ---- | -------- |
| `search_corpus` | 否 | `read_only_hint=True` |
| `read_chunk` | 否 | 同上（检索只给 240 字，原文走这里——**两个工具是配合设计**） |
| `review_question` | **是**（2~7 分） | `open_world_hint=True`；**默认关闭** + 单进程上限 5 次 |

**两个客户端都真接通了**：

- **Inspector**（`mcp dev`）：三个工具全调通，**过程中撞出 T46 / T47 / T49 / T50 四个缺陷**；
- **Codex**（`~/.codex/config.toml`）：会话里**直接调用** `search_corpus` → 8 条命中，
  再连调 5 次 `read_chunk` 核原文，产出带 6 条 `文件:页码` 引用的答案，并主动声明"只调用了只读、免费的两个工具"。

**四个缺陷全是"真接客户端才会遇到"的**（离线测试再全也测不到）：

| 条目 | 一句话 |
| ---- | ------ |
| T46 | `mcp dev` 用 `importlib` 按文件路径加载，**不把包目录加进 `sys.path`** |
| T47 | Inspector 拉起的子进程只带 `mcp==2.2.0`、**缺 `[cli]` extra** → 界面只显示 "Failed" |
| T48 | `get_retriever()` 里写了个**不存在的函数名**，而 9 条测试全绿——因为**全注入了假检索器，真路径没人走** |
| T49 / T50 | `read_chunk` 位置**只认一种拼法**（`第2页` / `第八页` / `第８页` 都不认），且**同一位置只返回一段**（真实索引一页 4~5 段） |

其中 T48 是这一阶段的**方法论**级教训，单独说一句：

> 测试里"能注入假件"是好事，但**至少得有一条走真路径**。
> 假件本身没错，错在真路径永远没人执行——这是 T43（少字段）、T44（走不到的分支）的第三例。

## 三、H3「让结论可被独立核对」：这条限制终于有了一条能走的路

项目最硬的限制是：**语料是机械/数控，作者不是这个方向**——没人能判"结论在专业上对不对"。
H3 的办法不是绕开它，而是**换一个问题问**：

> 不判"对不对"，只判"**这条结论能不能在它引用的原文里找到依据**"。

这个判断**不需要专业背景**，所以作者自己就能做——这才是 H3 的价值。

| 事 | 结论 | 证据 |
| -- | ---- | ---- |
| 核对清单生成器 | 一条命令把一次问答转成"结论 + 它引用的原文 + 支持/不支持/无法判断" | `web/audit.py`，8 条测试 |
| 真跑一轮 | **46 条结论 / 58 条精确引用 / 0 编造 / 0.1423 元**（三道真题） | `eval/核对清单-01/02/03-*.md` |
| 硬事实核对 | 把 46 条压成 **3 条**最该看的 | `eval/核对结论-首轮.md` |
| 逐条核的结果 | **2 支持 / 1 无法判断**（`HHT` 是模型自己补的） | 同上 |
| 回灌闭环 | 提示词加第 6 条规则 + `unsupported_facts()` 进管线 + 3 条测试 | `rag/review_qa.py` |
| 补资料 | 44 篇/2501 片段 → **56 篇/3073 片段**（AI 辅助工艺编制 5 篇 + NC 代码生成与校验 7 篇） | `eval/建库报告-56篇.md` |
| 补资料验证 | 三道题全部 `insufficient=False`，**结论引用落到新目录**（工艺编制那道从"资料中没有"变成引用新目录 15 条） | `eval/补资料验证-工艺编制与NC代码.md` |

**过程中改了我自己两次判断，都记了台账**：

- **T52**：第一版"挑重点"用的是"结论里的实词是否出现在引用原文里"——结果 **42/46 条全被标** = 噪声。
  根因很清楚：结论是对原文的**压缩改写**，用词天然不重合，**"词汇重合度"根本不携带"原文支持吗"这个信息**。
  换成**硬事实**（数字与英文型号，能被精确核对）后 46 条只剩 7 条被标，人工一看 **3 条是真问题**。
- **T53**：把"数在另一个候选里"一律叫"引用挂错"，而其中一条其实是**同一页的另一段**——
  引用是**页级**的，一页常切成 4~5 段，读者照着 `文件:第 2 页` 照样查得到。
  教训一句话：**"依据对不对"有多个粒度（片段 / 页 / 文件 / 全文），说清粒度比说清结论更重要。**

**还没做到的（不许含混过去）**：46 条里**只有 3 条经过逐条核对**，其余 **43 条记"未评估"**。
那份结论表里"支持 2 / 不支持 0 / 无法判断 1 / 未评估 43"就是实话。

## 四、H4「交付与复盘」：把"我能答什么"和"结果能带走"补上

| 事 | 结论 | 证据 |
| -- | ---- | ---- |
| 能力说明 | `rag/coverage.py` 是**唯一来源**（7 个子主题 / 3 条不覆盖 / 3 个示例），`/api/health` 吐给界面 | 界面截图、5 条测试 |
| 元问题不再检索 | 问"你能回答什么"**不检索、不花钱**，直接回能力说明 | 用"检索器一次都没被调用"断言 |
| 示例问题 | 提问框下三个可点 chip，**点了只填进输入框、不自动发送** | 冒烟断言 |
| 结果可导出 | `POST /api/export` → Markdown / JSON；**复用界面那份渲染**，中文文件名走 RFC 5987 | 7 条测试（含 2 条 HTTP 层） |

两个设计决定值得记：

1. **能力说明只能有一份**：文档与代码不一致**没有任何运行时症状**，只有"读者按文档理解、被现实打脸"。
   所以加了一致性测试（代码里 7 个子主题必须在 `使用说明.md` 里一个不少）——它**上线就抓到**
   `使用说明.md` 从来没列出过子主题（只有一句概述）；
2. **导出不写第二份渲染**：Markdown 直接复用 `render_view_markdown`，导出的就是你看到的。
   两份渲染器必然漂移，而漂移在"导出的文件"这种低频路径上最难被发现。

## 六、四条规律（这是本阶段真正的产出）

1. **假件要能派生，别手抄**：T43 少字段、T44 把走不到的分支测绿、T48 真路径无人走——
   同一个病的三种形态。治法是**夹具从真实产物生成 + 一条漂移检测**（已在 `tests/_web_fakes.py` 里机制化）。
2. **换个入口就撞上**：T40（中文口令）、T46（Inspector 的 importlib）、T47（子进程缺 extra）。
   同一个程序在"自己的 shell"里跑得好，不等于**别人会怎么用它**。所以 H2 的"用 Inspector 手动调通"
   不是走过场，它测的正是这件事。
3. **手抄输入不能只认一种写法**：T49（空格）、T50（中文数字、全角）。
   补了空格冒出中文数字，补了中文数字还会冒出全角——**见一个补一个治不了根**。
   真正兜底的是**错误信息里给可用的取值清单**，加上"能猜就猜"的宽松匹配（并把规范写法回给调用方）。
4. **本地绿不等于 CI 绿**：T51——`data/` 不进 Git，CI 上没有索引，
   而我那条测试里顺手写了个 `assert path.exists()`。要证明"位置对不对"就**对比路径**，别去戳磁盘。
