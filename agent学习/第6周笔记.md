# 第 6 周笔记：安全与护栏

日期：2026-09-08

## 一句话结论

护栏（guardrail）负责“自动检查”，人工审批（human review）负责“需要人拍板的敏感操作”。
前者用代码或模型自动拦截，后者让运行暂停，等人批准或拒绝后再继续同一轮任务。

## 三种护栏放在哪里

| 类型 | 检查时机 | 适合做什么 |
| --- | --- | --- |
| 输入护栏 input guardrail | 模型开始处理前 | 拦截明显违规或危险的用户请求 |
| 输出护栏 output guardrail | 最终回答返回前 | 检查、拦截或脱敏敏感内容 |
| 工具护栏 tool guardrail | 工具调用前后 | 检查工具参数和工具返回结果 |

注意两个边界：

- 输入护栏只在链路里的第一个 Agent 上运行；
- 输出护栏只在最终产出回答的 Agent 上运行。


关键代码：

```python
@input_guardrail(name="block_dangerous_operations", run_in_parallel=False)
def block_dangerous_operations(ctx, agent, user_input):
    ...
    return GuardrailFunctionOutput(
        output_info={"matched_patterns": matched},

```

`run_in_parallel=False` 表示护栏先于主 Agent 运行；如果 `tripwire_triggered=True`，
SDK 会抛出 `InputGuardrailTripwireTriggered`，主 Agent 不会继续执行。

## 实验二：敏感操作人工审批

运行：

```bash
python 06_human_approval.py              # 运行时询问 y/N
python 06_human_approval.py --decision approve
python 06_human_approval.py --decision reject
```

审批生命周期：

1. 模型决定调用 `delete_file`；
2. SDK 发现这个工具设置了 `needs_approval=True`，于是暂停运行；
3. `result.interruptions` 里出现待审批的 `ToolApprovalItem`；
4. 用 `result.to_state()` 拿到可恢复状态；
5. 调用 `state.approve(item)` 或 `state.reject(item)`；
6. 再执行 `Runner.run(agent, state)`，从暂停处继续。

验证结果（拒绝）：

```text
运行已暂停，等待人工审批：
- 工具：delete_file
  参数：{"path": "agent学习/临时文件.txt"}

审批结果： 拒绝
最终回答： 删除操作已被拒绝，因此 agent学习/临时文件.txt 未被删除。
```

验证结果（批准）：

```text
[工具已执行] delete_file(path=agent学习/临时文件.txt)

审批结果： 批准
最终回答： 文件 agent学习/临时文件.txt 已成功删除。
```
