# 个人资料问答助手：项目设计

> 第 8 周产出：确定项目范围，画出功能结构。
> 说明：这是建议方案，若你想改做“研究方向检索分析”或“自动化报告”，
> 可以直接替换本文件内容，不影响前面的学习代码。

## 1. 项目目标

做一个能读取本地 Markdown 笔记的问答 Agent。用户用中文提问，
Agent 必须先调用工具查找并阅读相关笔记，再回答，并在答案里注明来源文件。

MVP（第 9 周）只做最核心的一件事：

> 针对本地笔记目录提问，Agent 能找出相关文件、读出内容并给出带来源的回答。

## 2. 范围边界

本阶段要做：

- 读取本地 Markdown 笔记；
- 按关键词搜索笔记；
- 基于笔记内容回答问题；
- 回答里带来源文件名；
- 本地日志记录工具调用与最终回答。

本阶段不做：

- 向量数据库 / 语义检索；
- 联网搜索；
- 图形界面或网页；
- 删除、写入文件等有副作用操作（如以后要做，复用第 6 周审批机制）。

## 3. 功能结构

```text
用户提问
  ↓
notes_agent（DeepSeek 模型）
  ├── list_notes()            列出有哪些笔记文件
  ├── search_notes(keyword)   按关键词找相关笔记
  └── read_note(filename)     读取指定笔记内容
  ↓
带来源文件的回答
```

关键规则：

1. 回答前必须先调用 `search_notes` 或 `read_note`，不能凭记忆编造；
2. 笔记里没有答案时，明确说“笔记中没有找到”；
3. 回答格式固定为：结论 + 来源文件名。

## 4. 数据来源

第一版直接用已有的周笔记作为测试数据：

- `agent-learning/第4周笔记.md`
- `agent-learning/第5周笔记.md`
- `agent-learning/第6周笔记.md`

后续可以把目录指向你真正的学习笔记或资料目录。
